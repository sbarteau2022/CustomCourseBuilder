**Course:** AIE-201 — Machine Learning from First Principles (core tier)
**Module:** M03 of the descent arc (regression → **trees** → k-means → PCA)
**Duration:** 18 learner-hours
**Prerequisites:** AIE-201-M01 (generalization, capacity, the bias-variance bet), AIE-201-M02 (loss-plus-penalty structure, the arbitrary tie-break as a recurring failure mode), AIE-103 (gradients and information theory, hand-derived — entropy is used here, not just named), AIE-110 (recursion, complexity budgets)
**Toolchain:** Python 3.12+, NumPy, pandas, scikit-learn (verification only — never the primary implementation), pytest, matplotlib

## Module overview

Every algorithm in this module is one idea, applied three times at increasing scale. The idea:
**split the data on the feature and threshold that makes the two resulting groups as
label-pure as possible, and recurse.** That is a decision tree. Fit many of them to
bootstrap-resampled copies of the data and average their votes, and that is a random forest.
Fit them one at a time, each one correcting the specific residual error the ones before it
left behind, and that is gradient boosting. Nothing above the level of "one split, chosen
greedily" is new machinery — bagging and boosting are two different ways of *composing* the
same tree you will hand-build in Lesson 1, not two new algorithms to learn from scratch.

The descent is literal. Lesson 1 puts eight rows and one feature on paper and asks you to
hand-compute which threshold splits them best — by two different formulas (Gini impurity,
information gain) that will occasionally disagree about ties, never about direction. Lesson 2
turns that one hand-traceable split into a recursive `fit_tree` and immediately shows you the
tree's failure mode: given enough depth, it memorizes the training set perfectly and
generalizes badly, the exact capacity argument from AIE-201-M01 now made concrete in a
structure you built yourself. Lessons 3 and 4 are the two industrial answers to that failure —
bagging trades a high-variance tree for many decorrelated ones and averages away the variance;
boosting keeps a shallow, high-bias tree and chases down the bias a residual at a time. Both
are matched against their scikit-learn counterparts (`RandomForestClassifier`,
`GradientBoostingClassifier`/`GradientBoostingRegressor`) to a stated numerical standard — and
that standard is different for the two, which is itself a lesson: a *deterministic* tree can be
checked bit-for-bit; a *randomized* forest can only be checked by behavior, because two correct
implementations of a randomized algorithm are not obligated to draw the same random numbers.

This module also pays off something AIE-201-M02 planted deliberately. M02's Lasso Lab 3 proved,
in your own code, that when two features are highly correlated, a greedy algorithm's credit
assignment between them is an artifact of column order — swap the columns, the split swaps
with them. Lesson 1's Gini-tie worked example reproduces that *exact* phenomenon in a tree's
threshold selection. Lesson 3 then asks the harder question M02 could only gesture at:
does *averaging over many trees* fix the instability, or only disguise it? You will build the
experiment and get a real, numeric, not-entirely-comfortable answer.

Finally: this module treats "gradient boosting fits a tree to predict `y`" as a bug to correct,
not a simplification to tolerate. It fits a tree to the **negative gradient of the loss** —
which for squared error happens to equal the residual, but that equivalence is a special case,
and Lesson 4 shows you what changes (a lot) the moment the loss isn't squared error. This is
functional gradient descent, the same descent-the-loss-surface idea from AIE-103, except the
"step direction" at each iteration is a freshly-fit regression tree instead of a fixed-length
vector.

## Lessons

### Lesson 1 — Splitting on impurity: Gini and entropy, hand-computed on eight rows

**Teaching text**

A decision tree's entire "intelligence" is one repeated question: *of every feature and every
threshold I could split on, which one makes the two resulting groups least mixed?* "Least
mixed" needs a number, and this module uses two of them.

**Gini impurity** of a set of labels $S$ with class proportions $p_1, \ldots, p_k$:

$$G(S) = 1 - \sum_{c=1}^{k} p_c^2$$

It is the probability that two labels drawn independently (with replacement) from $S$
disagree. A pure set ($p_c=1$ for one class) has $G=0$; a maximally mixed binary set
($p_1=p_2=0.5$) has $G=0.5$.

**Entropy**, from AIE-103's information theory, applied here instead of merely defined there:

$$H(S) = -\sum_{c=1}^{k} p_c \log_2 p_c$$

A pure set has $H=0$; a maximally mixed binary set has $H=1$ bit. **Information gain** is the
entropy version of "how much did this split help":

$$IG = H(\text{parent}) - \left[\frac{n_L}{n}H(\text{left}) + \frac{n_R}{n}H(\text{right})\right]$$

and the Gini analogue — **Gini gain** — is the same expression with $G$ in place of $H$. Both
are concave impurity measures that are $0$ at purity and maximal at 50/50, and in practice they
pick the same split the overwhelming majority of the time. They are not the same function,
though, and this lesson's worked example is built specifically to show you a case where their
*numbers* differ (entropy's scale is bits, Gini's is a raw probability) while their *decision*
still agrees — because agreement-in-decision, not agreement-in-number, is the property that
matters for building a tree.

The greedy algorithm a **CART** (Classification and Regression Tree) implementation runs at
every node: for every feature, for every candidate threshold (the midpoints between consecutive
sorted unique values of that feature), compute the weighted child impurity; keep the
feature/threshold pair with the lowest weighted impurity (equivalently, the highest gain).
Recurse on the two resulting groups. This is the entire algorithm — the intelligence is
entirely in "try everything, keep the best," repeated recursively, exactly the kind of brute
greedy search AIE-110 taught you to cost out before trusting.

**Worked example**

Eight students, hours studied (`x`) versus pass/fail (`y`):

| x (hours) | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| y (pass) | 0 | 0 | 0 | 1 | 0 | 1 | 1 | 1 |

Root: 4 fails, 4 passes. $G(\text{root}) = 1 - (0.5^2+0.5^2) = 0.5$. $H(\text{root}) = 1.0$ bit.
Every candidate threshold is the midpoint between consecutive sorted x-values — seven of them,
`1.5` through `7.5`. Hand-compute the split at `t=3.5` (left = `{1,2,3}`, right = `{4,...,8}`):

- Left = `{0,0,0}`: pure. $G_L = 0$, $H_L = 0$.
- Right = `{1,0,1,1,1}`: 4 pass, 1 fail out of 5. $G_R = 1-((4/5)^2+(1/5)^2) = 1 - 17/25 = 0.32$.
  $H_R = -(0.8\log_2 0.8 + 0.2\log_2 0.2) \approx 0.7219$.
- Weighted Gini $= \frac{3}{8}(0) + \frac{5}{8}(0.32) = 0.2000$. Gini gain $= 0.5 - 0.2 = 0.3000$.
- Weighted entropy $= \frac{3}{8}(0) + \frac{5}{8}(0.7219) = 0.4512$. Info gain $= 1.0 - 0.4512 = 0.5488$.

Do this for all seven thresholds and you get the full table:

| t | n_L, n_R | weighted Gini | Gini gain | weighted entropy | info gain |
|---|---|---:|---:|---:|---:|
| 1.5 | 1, 7 | 0.4286 | 0.0714 | 0.8621 | 0.1379 |
| 2.5 | 2, 6 | 0.3333 | 0.1667 | 0.6887 | 0.3113 |
| **3.5** | 3, 5 | **0.2000** | **0.3000** | **0.4512** | **0.5488** |
| 4.5 | 4, 4 | 0.3750 | 0.1250 | 0.8113 | 0.1887 |
| **5.5** | 5, 3 | **0.2000** | **0.3000** | **0.4512** | **0.5488** |
| 6.5 | 6, 2 | 0.3333 | 0.1667 | 0.6887 | 0.3113 |
| 7.5 | 7, 1 | 0.4286 | 0.0714 | 0.8621 | 0.1379 |

**`t=3.5` and `t=5.5` tie exactly**, on both criteria. This is not a coincidence of this
particular dataset being hand-picked to be symmetric — it *is* hand-picked to be symmetric, on
purpose, so that the tie is guaranteed and reproducible rather than a rare numerical accident.
A real tree-building algorithm needs a deterministic rule for what to do when two candidates
tie, because "look at the numbers and pick the better one" has no answer here. This module's
scratch implementation (and, empirically, scikit-learn's `DecisionTreeClassifier` on this exact
data) resolves ties by **keeping the first split found while scanning thresholds in ascending
order** — i.e., a later candidate only replaces the current best if it is *strictly* better, not
merely equal. Under that rule, `t=3.5` is found first and wins; `scikit-learn` confirms it:
`DecisionTreeClassifier(max_depth=1).fit(x, y)` selects `threshold_ == 3.5`. Nothing about the
*data* favored 3.5 over 5.5 — the tie-break is a scanning-order convention, not a discovery
about the world. Hold that sentence; Lesson 3 comes back for it.

**Named misconceptions**

- **"The decision tree finds *the* best split."** The definite article claims uniqueness that
  the algorithm does not guarantee. This worked example ties exactly; real, non-toy datasets tie
  or near-tie constantly whenever two features carry overlapping signal (the M02 callback: this
  is the same phenomenon as Lasso's coordinate-order tie-break, wearing a different hat, and
  Lesson 3 makes the parallel exact).
- **"Entropy and Gini always agree, so it doesn't matter which one you pick."** They agree on
  *which split wins* far more often than they agree on the *number* — Gini gain and information
  gain are different scales measuring different quantities (a raw probability versus a bit
  count) that happen to be monotonically related for binary splits in most practical cases, not
  identically equal. Treat "Gini and entropy always pick the same tree" as an empirical tendency
  you should verify per-dataset, not a theorem you get to assume.
- **"A leaf with nonzero impurity means the algorithm failed to finish."** A leaf's impurity
  only has to reach zero if nothing stops the recursion first. Lesson 2 is built entirely around
  the fact that letting every leaf reach zero impurity is usually the *wrong* goal — it is also
  the definition of the tree that has memorized its training set.

### Lesson 2 — Growing the full tree: recursion, stopping rules, and a tree that memorizes

**Teaching text**

The full algorithm is the Lesson 1 split, called recursively:

```
fit_tree(X, y, depth):
    if stopping_condition(X, y, depth): return Leaf(majority_class_or_mean(y))
    feature, threshold = best_split(X, y)          # Lesson 1's scan, over every feature
    left, right = partition(X, y, feature, threshold)
    return Node(feature, threshold,
                left=fit_tree(left.X, left.y, depth+1),
                right=fit_tree(right.X, right.y, depth+1))
```

This is a direct AIE-110 recursion — same shape as any divide-and-conquer routine, with a
stopping condition standing in for the base case. The stopping condition is where all of a
tree's *hyperparameters* live: `max_depth` (a hard ceiling on recursion depth), `min_samples_leaf`
(refuse a split that would leave fewer than this many rows in either child), `min_samples_split`
(refuse to attempt a split at all below this many rows), and the free stopping condition every
tree gets automatically — a node whose labels are already pure has nothing left to gain from
splitting.

Cost, in AIE-110's terms: scanning one feature at one node costs $O(n)$ per threshold across
$O(n)$ candidate thresholds, so $O(n^2)$ per feature per node; across $p$ features that's
$O(n^2 p)$ per node. A balanced tree of depth $d$ visits roughly $n$ rows total per depth level,
so a full recursive build costs on the order of $O(n^2 p \, d)$ with this naive scan — the same
brute-force-then-optimize story as AIE-110's early lessons; production implementations
pre-sort each feature once and update running sums as the threshold slides, turning the
per-node cost to $O(np\log n)$. This module's scratch implementation uses the naive $O(n^2)$
scan deliberately, because it is the version whose correctness is checkable by eye against
Lesson 1's hand table; Lab 1's Verify step confirms it agrees with scikit-learn's optimized
version despite being asymptotically worse.

**Now the point of this lesson.** An unconstrained tree ($\text{max\_depth}=\text{None}$,
$\text{min\_samples\_leaf}=1$) can always drive every leaf to purity, given enough depth,
*provided no two rows have identical features and different labels* — every leaf keeps
splitting until it contains one row, or a run of rows with the same label. **Training accuracy
of an unconstrained tree is 1.0, always, structurally** — not a sign the tree learned the
pattern, a sign the tree memorized the sample. This is AIE-201-M01's bias-variance bet made
concrete: an unconstrained tree is a near-zero-bias, extremely-high-variance model family, and
`max_depth`/`min_samples_leaf` are literally the tree's capacity dial, playing the exact role
`alpha` played for Ridge in AIE-201-M02 — the mechanism is completely different (structural
recursion depth instead of a loss penalty) but the *job* — trading a little bias for a lot less
variance — is identical.

**Worked example**

The tiny eight-row dataset, fully grown (no depth limit), reaches training accuracy 1.0 at
**depth 3** — it needs three levels because `x=5` (a fail) sits alone in the middle of an
otherwise all-pass run from `x=4` to `x=8`, and isolating a single point in the middle of a run
costs one extra split beyond isolating a point at an edge:

```
feature_0 <= 3.50
├── (yes) class: 0
└── (no)  feature_0 <= 5.50
          ├── (yes) feature_0 <= 4.50
          │         ├── (yes) class: 1
          │         └── (no)  class: 0
          └── (no)  class: 1
```

On a larger, noisier synthetic dataset (`sklearn.datasets.make_classification`, `n=300`,
5 features, 3 informative, `random_state=42`, 70/30 train/test split), sweeping `max_depth`
shows the shape the tiny example only hints at:

| max_depth | train accuracy | test accuracy |
|---:|---:|---:|
| 1 | 0.8095 | 0.8111 |
| 2 | 0.8238 | 0.8111 |
| 3 | 0.8714 | 0.8556 |
| 4 | 0.9095 | 0.8556 |
| None (unconstrained) | **1.0000** | 0.8444 |

Train accuracy is monotonically nondecreasing in depth — it structurally cannot go down, since
more depth can only give the tree more ways to fit the training rows it already sees. Test
accuracy is **not** monotonic: it climbs through depth 3–4 and then *drops* at unconstrained
depth, even though the unconstrained tree has strictly higher capacity and a strictly lower
training loss than every shallower tree in the table. Capacity bought training accuracy it did
not need and generalization it actively lost.

**Named misconceptions**

- **"A tree with 100% training accuracy is a good tree."** It is a tree that has run out of
  training rows to disagree with it. Whether that generalizes is a separate, empirical question
  — the same "the bet has to be checked, not assumed" argument from AIE-201-M01 — and the table
  above answers it here with a real number: no, not on this dataset.
- **"Pruning/depth-limiting is optional polish you add if you have time."** It is the tree's
  entire regularization mechanism — there is no other knob. An unpruned tree on real data is not
  "the honest version" of a pruned one; it is a different point on the bias-variance curve,
  usually a worse one for anything you plan to deploy.
- **"More features can only help, since the tree can always ignore an irrelevant one at split
  time."** On small samples, an irrelevant feature can *appear* to beat a real one at a given
  node purely from sampling noise — with enough candidate thresholds tried, some noise feature
  will occasionally produce a higher apparent gain than the true signal by chance alone. This
  is exactly why Lesson 3's random forest restricts the feature *set* considered at each split,
  not just the training rows.

### Lesson 3 — Bagging: bootstrap aggregating turns variance into signal (Random Forest)

**Teaching text**

Lesson 2 established that an expressive tree is low-bias, high-variance: retrain it on a
slightly different sample and you can get a meaningfully different tree. **Bagging** (bootstrap
**agg**regat**ing**) turns that instability into an averaging opportunity instead of a liability.
Draw $B$ **bootstrap samples** — each one, $n$ rows drawn *with replacement* from the original
$n$-row training set — fit one tree per bootstrap sample, and combine: average the predictions
for regression, majority-vote for classification.

The variance math, straight from AIE-103's probability rules: if you average $B$ estimators,
each with variance $\sigma^2$, and each pair correlated at $\rho$:

$$\text{Var}\!\left(\frac{1}{B}\sum_{b=1}^B \hat f_b(x)\right) = \rho\sigma^2 + \frac{(1-\rho)\sigma^2}{B}$$

As $B \to \infty$, the second term vanishes and variance approaches a **floor of $\rho\sigma^2$**
— set by how *correlated* the trees are, not by how many of them you fit. Bootstrap resampling
alone gives you some decorrelation (each tree sees a different, overlapping 63.2% of the
original rows — each bootstrap draw leaves out a given row with probability
$(1-1/n)^n \to e^{-1} \approx 36.8\%$, which is where **out-of-bag (OOB)** validation comes
from: score each row using only the trees that never trained on it, a free held-out estimate
with no separate validation split). Bootstrap resampling alone is *not enough* decorrelation on
its own, though, because every tree still sees every feature and, on real data, greedily
gravitates toward the same strongest signal first. **Random forest** adds a second
randomization on top: at every split, restrict the candidate feature set to a random subset
(conventionally $\sqrt{p}$ for classification) instead of all $p$ features. This is the
mechanism that drives $\rho$ down further than bootstrap resampling can alone, which is why
"random forest" earns a different name from plain bagged trees rather than being a marketing
relabel.

One consequence of the $\rho\sigma^2$ floor is worth stating as a fact, not a hedge: **you
cannot overfit a random forest by adding more trees.** Each additional tree is fit
independently of the ones before it, on its own bootstrap draw; more trees can only move the
ensemble's variance down toward the $\rho\sigma^2$ floor, never up. This is the single clearest
structural difference from Lesson 4's boosting, where more rounds keeps chasing training error
and absolutely can make things worse — hold onto this contrast; the labs test both halves of
it directly.

**Worked example — variance actually shrinking**

Ground truth $f^*(x)=\sin(2\pi x)$, one feature, evaluated at $x_0=0.3$
($f^*(0.3)\approx 0.9511$). Redraw the training sample ($n=50$, fresh noise) 30 independent
times; for each redraw, fit one high-variance tree (`max_depth=8, min_samples_leaf=1`) and one
100-tree forest of the same base learner, and record each model's prediction at $x_0$:

| Model | mean prediction | variance across 30 redraws | bias |
|---|---:|---:|---:|
| single tree | 0.9395 | **0.0567** | −0.012 |
| forest, B=100 (no feature subsampling — only 1 feature exists) | 0.9374 | **0.0280** | −0.014 |

Variance drops by roughly half, bias is essentially unchanged — exactly the trade the formula
predicts, and exactly the trade Ridge made in AIE-201-M02 by a completely different mechanism.
With only one feature in this example, feature subsampling has nothing to decorrelate (there is
only one feature to sample), which is precisely why the reduction here comes from bootstrap
resampling alone and stops well short of driving variance toward zero — the $\rho\sigma^2$
floor, made visible.

**Worked example — the tie-break, averaged, not erased**

Recall Lesson 1's promise: does averaging over many trees fix the correlated-feature tie-break,
or only disguise it? Build a dataset where the answer is checkable: `f0` and `f1` are both
`z + small_noise` for a shared latent `z` (correlation ≈ 0.999, same construction as AIE-201-M02's
Lab 3), `f2`/`f3` are pure noise, and `y` depends only on `z`. Compute impurity-based feature
importance — the total Gini-gain each feature is credited with, summed over every split in every
tree, normalized to sum to 1 — for a single tree, and for random forests of size $B=10$ and
$B=50$, both with the original column order and with `f0`/`f1` swapped:

| Model | importance(f0) | importance(f1) | importance(f0), columns swapped | importance(f1), columns swapped |
|---|---:|---:|---:|---:|
| single tree (all features, no subsampling) | 0.999 | 0.001 | 0.005 | 0.995 |
| forest, B=10 (`max_features="sqrt"`) | 0.445 | 0.527 | 0.426 | 0.542 |
| forest, B=50 (`max_features="sqrt"`) | 0.635 | 0.346 | 0.521 | 0.458 |

The single tree reproduces the M02 Lasso result almost exactly: near-total winner-take-all
credit to whichever correlated feature happens to sit first, and it **flips completely** under
a column swap — 0.999/0.001 becomes 0.005/0.995. Averaging over 10 or 50 trees *damps* the
effect substantially (0.999-vs-0.001 becomes something closer to 0.4-vs-0.5, then 0.6-vs-0.3)
— genuinely closer to reflecting that `f0` and `f1` carry equally real, shared signal. But look
at the swapped columns: at *every* forest size, the swapped run's numbers are close to, but
measurably different from, the original run's numbers, and neither forest size lands on an
even 50/50 split. **Averaging over many trees makes the tie-break less extreme. It does not
make it column-order-invariant, and it does not converge smoothly toward parity as $B$ grows** —
compare the $B=10$ and $B=50$ rows and notice the gap between `f0` and `f1` actually *widens*
between them before either reaches a stable value. Random forest feature importance for
correlated features is a real, useful, imperfect signal, and the imperfection is not a bug you
fix by fitting more trees.

**Named misconceptions**

- **"Random forest is basically fitting the same tree many times on the same data."** Without
  bootstrap resampling *and* feature subsampling, every tree in the "ensemble" is close to
  identical, $\rho \approx 1$, and the variance floor $\rho\sigma^2$ barely improves on a single
  tree. Both randomizations are load-bearing; either one alone gets you partway.
- **"More trees always keeps helping, so just set `n_estimators` as high as you can afford."**
  True that it never hurts (the "can't overfit by adding trees" fact above), false that it
  keeps helping indefinitely — past the point where the ensemble's variance has converged near
  the $\rho\sigma^2$ floor, additional trees cost training time and inference latency for
  a vanishing accuracy return. "Never hurts" and "keeps helping" are different claims; only the
  first is true without qualification.
- **"Because the forest averages many trees, its feature importance ranking is now a solid,
  order-independent measurement I can report as which features matter."** The worked example
  above is a direct, numeric refutation, built from the exact mechanism Lesson 1 named. Averaging
  reduces the instability's *magnitude*; it does not eliminate the instability, and the module's
  Tier 3 reading returns to exactly this gap with real stakes attached.

### Lesson 4 — Boosting: gradient boosting fits trees to the gradient, not the labels

**Teaching text**

Bagging fits $B$ trees **independently**, in parallel, to reduce variance. **Gradient
boosting** fits $M$ trees **sequentially**, each one deliberately targeting what the ensemble
so far still gets wrong, to reduce *bias*. This is functional gradient descent — the same
descend-the-loss-surface idea AIE-103 hand-derived and AIE-201-M02 Lesson 2 implemented as
`w -= lr * grad`, except here the thing being updated is not a coefficient vector but a whole
function $F(x)$, and the "gradient step" at each iteration is not a fixed-direction vector but
a freshly-fit regression tree.

Start with a constant model, $F_0(x) = \bar y$ (the training mean, for squared-error loss). At
round $m$, compute the **negative gradient of the loss with respect to the current predictions**
— evaluated pointwise, at every training row, holding everything else fixed:

$$r_i^{(m)} = -\left.\frac{\partial}{\partial F(x_i)}\, \ell\!\left(y_i, F(x_i)\right)\right|_{F=F_{m-1}}$$

For squared-error loss, $\ell = \frac{1}{2}(y-F)^2$, and this derivative works out to the plain
residual: $r_i^{(m)} = y_i - F_{m-1}(x_i)$. **This is a special case, not the definition of
boosting** — fit a small regression tree $h_m$ to predict $r^{(m)}$ from $x$ (a regression tree,
even for a classification target, because the pseudo-residual is a continuous quantity), then
update:

$$F_m(x) = F_{m-1}(x) + \eta \cdot h_m(x)$$

where $\eta$ (the **learning rate**, also called shrinkage) is a small step size, exactly the
same overshoot-versus-crawl trade-off as AIE-201-M02's gradient descent learning rate — and,
critically, the same divergence risk: too large an $\eta$ doesn't converge faster, it overshoots
and the loss can get *worse* than an earlier round's, a direct callback to M02's `lr=3.0`
divergence.

**Bagging reduces variance; boosting reduces bias.** This single sentence is the entire
structural contrast, and it explains two things that otherwise look like arbitrary facts to
memorize: (1) boosting's base learners are deliberately *shallow* (`max_depth` of 2–4 is typical,
versus bagging's often-unconstrained trees) — a boosted ensemble gets its expressiveness from
*accumulating* many weak, biased trees, not from any single tree being powerful; (2) unlike
bagging, boosting rounds are **not** free — because each round explicitly re-targets the current
training residual, more rounds strictly reduces training error and, past some point, that keeps
happening *after* test error has started rising. "You can't overfit a random forest by adding
trees" from Lesson 3 has no boosting analogue: you absolutely can, and do, overfit gradient
boosting by adding rounds.

**Outliers.** The squared-error gradient is the raw residual $y_i - F(x_i)$ — unbounded, and
*linear in the size of the error*. One badly wrong training point with a residual of 8 keeps
generating a pseudo-residual of roughly 8 (or whatever's left after each round's partial
correction) every single round until the ensemble has spent enough tree capacity closing that
gap — capacity taken directly from fitting the rest of the data. Swap to the **absolute-error**
loss, $\ell = |y - F|$, and its negative gradient is $\text{sign}(y-F)$ — magnitude exactly 1,
*regardless of how wrong the point is*. A residual of 8 and a residual of 0.8 generate the
identical-magnitude pseudo-residual under absolute error; only the *direction* differs. This is
the exact non-differentiability-at-zero story from AIE-201-M02's Lasso, now doing robustness
work instead of sparsity work — bounded (sub)gradients are what keep one extreme point from
dominating every subsequent round.

**Missing values — check the estimator, not the algorithm family.** "Tree-based models handle
missing data" is not a property of "being a tree" — it is a property of a *specific
implementation choosing to build NaN-routing into its split logic*, and different estimators
in the same library make different choices, which also change across versions. Verified
directly against the toolchain this course runs (`scikit-learn 1.9`): `DecisionTreeClassifier`
and `RandomForestClassifier` fit successfully on data containing `NaN` (both learned missing-
value routing as part of their normal split-finding, sending each node's missing values down
whichever child minimizes impurity — a behavior added to scikit-learn in version 1.4, not
present in earlier releases); the classic `GradientBoostingClassifier` — the estimator this
module targets — **raises `ValueError: Input X contains NaN`** and requires imputation before
fitting; `HistGradientBoostingClassifier`, a different, histogram-based implementation not
covered in this module, accepts `NaN` natively. Three estimators built from the same family of
base learner, three different missing-value contracts, one of them worse than the other two —
this is precisely why "I checked with `X.isna().sum()` and picked an estimator" beats
"trees handle missing data, so I don't need to check."

**Worked example**

Sinusoidal regression data ($n=300$, $y = \sin(2\pi x) + \mathcal{N}(0, 0.2^2)$), `max_depth=2`,
`min_samples_leaf=5`, `learning_rate=0.1`, sweeping the number of boosting rounds:

| n_estimators | train MSE | test MSE |
|---:|---:|---:|
| 1 | 0.4628 | 0.4433 |
| 10 | 0.1297 | 0.1197 |
| **50** | 0.0307 | **0.0445** |
| 100 | 0.0280 | 0.0458 |
| 300 | 0.0215 | 0.0510 |

Train MSE falls monotonically, every round, as the algorithm's structure guarantees it must.
Test MSE bottoms out around round 50 and then **rises** through round 300, even as train MSE
keeps falling — the single cleanest overfitting signature in this module, and the direct proof
of the "boosting rounds are not free" claim above. (This scratch implementation matches
`sklearn.ensemble.GradientBoostingRegressor` on identical hyperparameters to floating-point
precision — max absolute prediction difference on held-out data: `2.22e-16`, i.e. one machine
epsilon. Unlike Lab 2's randomized forest, gradient boosting as built here has no internal
randomness of its own to disagree about, so an exact match is the right standard to hold it to,
not an aspiration.)

Learning rate, at a fixed 50 rounds:

| learning rate | train MSE | test MSE |
|---:|---:|---:|
| 0.01 | 0.2532 | 0.2369 |
| 0.10 | 0.0307 | 0.0445 |
| 0.50 | 0.0216 | 0.0526 |
| 1.00 | 0.0159 | 0.0538 |
| **2.00** | **0.5476** | **0.4672** |

`lr=2.0` doesn't converge to a worse point slowly — it overshoots so badly that both train and
test error land *worse than `lr=0.01`'s barely-converged result*, the boosting analogue of
M02's exploding-loss divergence at too-high a gradient descent learning rate.

Outlier robustness — one training point at $x=0.5$ shifted by $+8.0$, measuring RMSE against
the *true, uncorrupted* function, split by distance from the outlier's location:

| Model | RMSE within 0.05 of the outlier | RMSE elsewhere |
|---|---:|---:|
| Random forest (B=200, bagging) | 0.633 | 0.080 |
| Gradient boosting, squared-error loss | **1.224** | 0.068 |
| Gradient boosting, absolute-error loss | 0.165 | 0.161 |

Squared-error boosting is *nearly twice as wrong* near the outlier as the random forest built
from the same base learner on the same corrupted data — direct, measured confirmation of the
residual-chasing mechanism above. Absolute-error boosting's error near the outlier is close to
its error everywhere else, which is exactly what "the gradient magnitude doesn't scale with how
wrong the point is" predicts.

**Named misconceptions**

- **"Gradient boosting fits each new tree to predict $y$, same as bagging, just one after
  another."** Every tree after the first is fit to the *current pseudo-residual*, a target that
  changes shape every round as $F_{m-1}$ improves — the trees in a boosted ensemble are not
  interchangeable predictors of $y$ the way bagged trees are, and cannot be reordered or
  subsetted the way a forest's trees can (dropping the first boosting tree breaks every tree
  fit after it; dropping a bagged tree just shrinks $B$).
- **"A higher learning rate just trains faster, with no real downside."** The `lr=2.0` row
  above is worse on *both* train and test error than `lr=0.01` — this is not "faster but
  slightly riskier," it is the same overshoot-and-diverge failure mode from AIE-201-M02's
  gradient descent, now with a tree-fitting step in place of a vector step.
- **"Ensembles are made of trees, and trees handle missing values, so ensembles handle missing
  values."** False for exactly one of this module's two target estimators, verified by running
  the code, not by category membership — `RandomForestClassifier` does, `GradientBoostingClassifier`
  does not, on the scikit-learn version this course pins. Precision about *which specific class,
  which specific version* is the entire lesson, the same discipline M02 demanded when it derived
  the exact `alpha` conversion factor between this module's math and sklearn's API instead of
  eyeballing "roughly more regularization."

Solution (`dtree_solution.py`) — the full, verified implementation:

```python
import numpy as np


class Node:
    __slots__ = ("feature", "threshold", "left", "right", "value", "nan_goes_left")

    def __init__(self, feature=None, threshold=None, left=None, right=None,
                 value=None, nan_goes_left=True):
        self.feature = feature
        self.threshold = threshold
        self.left = left
        self.right = right
        self.value = value
        self.nan_goes_left = nan_goes_left

    def is_leaf(self):
        return self.value is not None


def gini(y):
    if len(y) == 0:
        return 0.0
    _, counts = np.unique(y, return_counts=True)
    p = counts / len(y)
    return 1.0 - np.sum(p ** 2)


def entropy(y):
    if len(y) == 0:
        return 0.0
    _, counts = np.unique(y, return_counts=True)
    p = counts / len(y)
    return -np.sum(p * np.log2(p))


def var_impurity(y):
    """Regression impurity: variance (drives MSE-reduction splits)."""
    return np.var(y) if len(y) else 0.0


IMPURITY = {"gini": gini, "entropy": entropy}


def _scan(X, y, feature_subset, min_samples_leaf, impurity_fn):
    n = len(y)
    parent_impurity = impurity_fn(y)
    best = {"gain": -np.inf, "feature": None, "threshold": None}
    for feat in feature_subset:
        col = X[:, feat]
        finite_mask = ~np.isnan(col)
        finite_vals = np.unique(col[finite_mask])
        if len(finite_vals) < 2:
            continue
        thresholds = (finite_vals[:-1] + finite_vals[1:]) / 2.0
        for t in thresholds:
            left_mask = finite_mask & (col <= t)
            right_mask = finite_mask & (col > t)
            n_left, n_right = left_mask.sum(), right_mask.sum()
            if n_left < min_samples_leaf or n_right < min_samples_leaf:
                continue
            w_impurity = (n_left / n) * impurity_fn(y[left_mask]) + \
                         (n_right / n) * impurity_fn(y[right_mask])
            gain = parent_impurity - w_impurity
            if gain > best["gain"] + 1e-12:      # strictly better -> replace; ties keep first-found
                best = {"gain": gain, "feature": feat, "threshold": t}
    return best


def best_split(X, y, criterion, feature_subset, min_samples_leaf):
    return _scan(X, y, feature_subset, min_samples_leaf, IMPURITY[criterion])


def best_split_regression(X, y, feature_subset, min_samples_leaf):
    return _scan(X, y, feature_subset, min_samples_leaf, var_impurity)


def leaf_value(y, task):
    if task == "classification":
        vals, counts = np.unique(y, return_counts=True)
        return vals[np.argmax(counts)]
    return float(np.mean(y))


def fit_tree(X, y, task="classification", criterion="gini", max_depth=None,
             min_samples_leaf=1, min_samples_split=2, max_features=None,
             rng=None, depth=0):
    n, p = X.shape
    node_pure = (len(np.unique(y)) == 1) if task == "classification" else np.allclose(y, y[0])
    stop = node_pure or n < min_samples_split or (max_depth is not None and depth >= max_depth)
    if stop:
        return Node(value=leaf_value(y, task))

    if max_features is None or max_features >= p:
        feature_subset = np.arange(p)
    else:
        feature_subset = rng.choice(p, size=max_features, replace=False)

    split = (best_split(X, y, criterion, feature_subset, min_samples_leaf)
             if task == "classification"
             else best_split_regression(X, y, feature_subset, min_samples_leaf))
    if split["feature"] is None:
        return Node(value=leaf_value(y, task))

    feat, t = split["feature"], split["threshold"]
    col = X[:, feat]
    finite_mask = ~np.isnan(col)
    left_mask = finite_mask & (col <= t)
    right_mask = finite_mask & (col > t)

    nan_mask = ~finite_mask
    nan_goes_left = left_mask.sum() >= right_mask.sum()   # send NaNs to the larger child
    if nan_goes_left:
        left_mask = left_mask | nan_mask
    else:
        right_mask = right_mask | nan_mask

    left = fit_tree(X[left_mask], y[left_mask], task, criterion, max_depth,
                     min_samples_leaf, min_samples_split, max_features, rng, depth + 1)
    right = fit_tree(X[right_mask], y[right_mask], task, criterion, max_depth,
                      min_samples_leaf, min_samples_split, max_features, rng, depth + 1)
    return Node(feature=feat, threshold=t, left=left, right=right, nan_goes_left=nan_goes_left)


def predict_one(node, x):
    while not node.is_leaf():
        v = x[node.feature]
        if np.isnan(v):
            node = node.left if node.nan_goes_left else node.right
        elif v <= node.threshold:
            node = node.left
        else:
            node = node.right
    return node.value


def predict_tree(node, X):
    return np.array([predict_one(node, x) for x in X])


class DecisionTree:
    def __init__(self, task="classification", criterion="gini", max_depth=None,
                 min_samples_leaf=1, min_samples_split=2, max_features=None, random_state=None):
        self.task = task
        self.criterion = criterion
        self.max_depth = max_depth
        self.min_samples_leaf = min_samples_leaf
        self.min_samples_split = min_samples_split
        self.max_features = max_features
        self.random_state = random_state

    def fit(self, X, y):
        rng = np.random.default_rng(self.random_state) if self.max_features else None
        self.root_ = fit_tree(np.asarray(X, dtype=float), np.asarray(y), self.task,
                               self.criterion, self.max_depth, self.min_samples_leaf,
                               self.min_samples_split, self.max_features, rng)
        return self

    def predict(self, X):
        return predict_tree(self.root_, np.asarray(X, dtype=float))

    def score(self, X, y):
        preds = self.predict(X)
        if self.task == "classification":
            return np.mean(preds == np.asarray(y))
        y = np.asarray(y)
        return 1 - np.sum((y - preds) ** 2) / np.sum((y - y.mean()) ** 2)
```

```python
import numpy as np
from dtree_solution import DecisionTree, gini


class RandomForest:
    def __init__(self, n_estimators=100, max_depth=None, max_features="sqrt",
                 min_samples_leaf=1, task="classification", random_state=None):
        self.n_estimators = n_estimators
        self.max_depth = max_depth
        self.max_features = max_features
        self.min_samples_leaf = min_samples_leaf
        self.task = task
        self.random_state = random_state

    def fit(self, X, y):
        X = np.asarray(X, dtype=float)
        y = np.asarray(y)
        n, p = X.shape
        if self.max_features == "sqrt":
            mf = max(1, int(np.sqrt(p)))
        elif self.max_features is None:
            mf = p
        else:
            mf = self.max_features

        rng = np.random.default_rng(self.random_state)
        self.trees_, self.oob_masks_ = [], []
        for _ in range(self.n_estimators):
            boot_idx = rng.integers(0, n, size=n)
            oob_mask = np.ones(n, dtype=bool)
            oob_mask[np.unique(boot_idx)] = False
            tree_seed = int(rng.integers(0, 2**31 - 1))
            tree = DecisionTree(task=self.task, max_depth=self.max_depth,
                                 min_samples_leaf=self.min_samples_leaf,
                                 max_features=mf, random_state=tree_seed)
            tree.fit(X[boot_idx], y[boot_idx])
            self.trees_.append(tree)
            self.oob_masks_.append(oob_mask)
        self._X_train, self._y_train = X, y
        return self

    def predict(self, X):
        X = np.asarray(X, dtype=float)
        preds = np.array([t.predict(X) for t in self.trees_])
        if self.task == "classification":
            out = np.empty(X.shape[0], dtype=preds.dtype)
            for i in range(X.shape[0]):
                vals, counts = np.unique(preds[:, i], return_counts=True)
                out[i] = vals[np.argmax(counts)]
            return out
        return preds.mean(axis=0)

    def score(self, X, y):
        preds = self.predict(X)
        if self.task == "classification":
            return np.mean(preds == np.asarray(y))
        y = np.asarray(y)
        return 1 - np.sum((y - preds) ** 2) / np.sum((y - y.mean()) ** 2)

    def oob_score(self):
        n = self._X_train.shape[0]
        votes = [[] for _ in range(n)]
        for tree, oob_mask in zip(self.trees_, self.oob_masks_):
            idx = np.where(oob_mask)[0]
            if len(idx) == 0:
                continue
            for i, p in zip(idx, tree.predict(self._X_train[idx])):
                votes[i].append(p)
        correct, total = 0, 0
        for i in range(n):
            if not votes[i]:
                continue
            vals, counts = np.unique(votes[i], return_counts=True)
            correct += (vals[np.argmax(counts)] == self._y_train[i])
            total += 1
        return correct / total

    def feature_importances(self, n_features):
        importances = np.zeros(n_features)

        def walk(node, X, y):
            if node.is_leaf():
                return
            n = len(y)
            col = X[:, node.feature]
            nan_mask = np.isnan(col)
            if node.nan_goes_left:
                left_mask = nan_mask | ((~nan_mask) & (col <= node.threshold))
            else:
                left_mask = (~nan_mask) & (col <= node.threshold)
            right_mask = ~left_mask
            gain = (gini(y)
                    - (left_mask.sum() / n) * gini(y[left_mask])
                    - (right_mask.sum() / n) * gini(y[right_mask]))
            importances[node.feature] += (n / len(self._y_train)) * gain
            walk(node.left, X[left_mask], y[left_mask])
            walk(node.right, X[right_mask], y[right_mask])

        for tree in self.trees_:
            walk(tree.root_, self._X_train, self._y_train)
        importances /= len(self.trees_)
        total = importances.sum()
        return importances / total if total > 0 else importances
```

```python
def correlated_data(swap=False):
```

```python
import numpy as np
from dtree_solution import DecisionTree


def squared_error_grad(y, F):
    return y - F


def absolute_error_grad(y, F):
    return np.sign(y - F)


LOSSES = {"squared_error": squared_error_grad, "absolute_error": absolute_error_grad}


class GradientBoosting:
    def __init__(self, n_estimators=100, learning_rate=0.1, max_depth=2,
                 min_samples_leaf=5, loss="squared_error", random_state=None):
        self.n_estimators = n_estimators
        self.learning_rate = learning_rate
        self.max_depth = max_depth
        self.min_samples_leaf = min_samples_leaf
        self.loss = loss
        self.random_state = random_state

    def fit(self, X, y):
        X = np.asarray(X, dtype=float)
        y = np.asarray(y, dtype=float)
        grad_fn = LOSSES[self.loss]
        self.init_ = float(np.mean(y)) if self.loss == "squared_error" else float(np.median(y))
        F = np.full(y.shape, self.init_)
        self.trees_, self.train_loss_ = [], []
        for _ in range(self.n_estimators):
            pseudo_residual = grad_fn(y, F)
            tree = DecisionTree(task="regression", max_depth=self.max_depth,
                                 min_samples_leaf=self.min_samples_leaf)
            tree.fit(X, pseudo_residual)
            F = F + self.learning_rate * tree.predict(X)
            self.trees_.append(tree)
            self.train_loss_.append(float(np.mean((y - F) ** 2)))
        return self

    def predict(self, X, n_estimators=None):
        X = np.asarray(X, dtype=float)
        F = np.full(X.shape[0], self.init_)
        trees = self.trees_ if n_estimators is None else self.trees_[:n_estimators]
        for tree in trees:
            F = F + self.learning_rate * tree.predict(X)
        return F
```

something closer to even, learners frequently stop there and report "random forest solves the

swapped-column row in their own table and ask them to compute `abs(imp[0] - imp[1])` for both
the original and swapped run at each $B$ — the nonzero, swap-sensitive gap at every forest size
is the thing to notice, and it's already sitting in data they generated themselves. This
should feel like a second, smaller version of the same struggle as the single-tree flip, not
a new lesson requiring new material.

**The wall: "gradient boosting is just a forest that goes one tree at a time," carried over
from Lesson 3's "more trees never hurts."** Learners who internalized Lesson 3's "you can't
overfit a random forest by adding trees" correctly often import that rule wholesale into
Lesson 4 and are then surprised — sometimes defensively so — when their test MSE rises past
round 50 in the worked example. **Reroute:** before debugging hyperparameters, have them plot
`train_loss_` against a held-out `val_loss_` they compute themselves, round by round. Seeing
train loss fall every single round while validation loss turns upward partway through is more
convincing, and faster to accept, than being told the two ensemble types differ.

**Accelerate condition.** A learner who, unprompted, asks "what happens if I fit the next tree
to something other than the raw residual" before Lesson 4 formally introduces the
negative-gradient framing — typically while still working through Lesson 3's bagging code and
noticing that boosting-flavored blog posts they've half-read don't match what bagging is doing —
is ready to skip Lesson 4's worked example and go straight to deriving
`squared_error_grad`/`absolute_error_grad` themselves as Lab 3's first Build step, checking their
derivation against the solution rather than reading the derivation first.

**Struggle triage, condensed:**

| Symptom | Productive (let it run) | Blocked (intervene) |
|---|---|---|
| Single-tree importance flips under column swap, learner rechecking `best_split`'s tie-break logic | Yes — this is the module's central "sit with this" moment, same shape as M02's Lasso swap | If they've concluded their Gini implementation is wrong and are rewriting `gini()` rather than examining the comparison operator in `best_split` |

## Three-tier reading — the forest's explanation, held up to the light

**Tier 1 — material ground.** Random forests and gradient-boosted trees are, by a wide margin,
the dominant model family for structured/tabular prediction in production — credit
underwriting, fraud detection, insurance pricing, clinical risk scores, ad ranking — chosen
specifically because they need little feature preprocessing and expose a `feature_importances_`
ranking that product teams, auditors, and regulators can point to and say "this is what the
model uses." This is documented and defensible: for tabular data, tree ensembles frequently
outperform other model families with less tuning, and a ranked importance list genuinely is
more auditable than an opaque model with no comparable output at all.

**Tier 2 — what "the forest ranked it" suppresses.** Lab 2's swap test is this tier made
checkable in your own code, not a hypothetical. When a deployed random forest's
`feature_importances_` ranks `years_at_current_address` above `zip_code` because the two were
correlated at 0.9 in training data, the sentence that reaches a regulator or a loan applicant —
"the model relies on years at address, not zip code, so it isn't using geography as a proxy" —
is treating a bootstrap-and-feature-subsampling artifact as a discovery about the world. You
measured, directly, that averaging over many trees *damps* this instability without erasing it:
the swapped-column run's importances differ from the original run's at every forest size you
tested, and neither converges to an even split. A `feature_importances_` ranking is real
evidence about what the fitted model happens to be doing with *this* `random_state` and *this*
column ordering — treating it as evidence about which real-world quantity "matters" requires an
argument the ranking itself does not supply, and reporting on tree ensembles' fairness or
explainability rarely draws that distinction, largely for the same reason M02's reporting on
Lasso rarely did: the ranking is easy to produce and reads as authoritative regardless of how
it was produced.

**Tier 3 — sit with this.** An insurer's random forest risk model ranks `prior_claims_count`
above `zip_code` in its `feature_importances_` output this quarter. Compliance cites that
ranking as evidence the model doesn't use geography — a known proxy for race and income — as a
meaningful input. You know, because you measured it yourself in Lab 2, that a different
`random_state`, or the routine addition of one more feature correlated with `zip_code`, could
plausibly reorder that ranking without the model's actual predictions — the premiums it
assigns, the people it flags — changing in any way a policyholder would notice or a regulator
could detect from the outputs alone. The ranking that gets cited in the compliance memo is not
a stable property of the underlying risk; it is a stable-*looking* readout of an unstable
computation, and nothing in the standard reporting workflow — the ranked bar chart, the top-5
feature list — carries a warning label saying so. If "the model doesn't rely on zip code" is
technically an accurate description of one `feature_importances_` array from one training run
with one random seed, and technically inaccurate as a claim about what the model would report
under the next retrain, which statement is compliance actually making — and does anyone in that
approval chain have the standing, the incentive, or the tooling installed to tell the
difference before the memo goes out?
