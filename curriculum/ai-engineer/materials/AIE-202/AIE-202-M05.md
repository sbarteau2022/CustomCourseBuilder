## The engine so far, and what this module adds

M03 rebuilt M01's scalar `Value` into an array-backed `Tensor` for the CNN build; M04 deliberately stepped back to scalars for one module to make a specific number (`|dL/dx_0|`, collapsing across timesteps) inspectable one Python float at a time. This module returns to the `Tensor` engine, exactly where M03 left it, and extends it with five things: three small arithmetic conveniences (`__neg__`, `__sub__`, `__truediv__`, plus `__radd__`/`__rmul__` so a bare Python float can sit on the *left* of an expression) and two **fused** operations — `softmax` and `layernorm` — whose backward pass is a single hand-derived vectorized formula rather than a composition of smaller primitives. Read the whole file below once; you will call every method in it before this module ends.

```python
# tensor.py — the engine, as of M03, plus this module's five additions
# (marked below). Everything above that marker is unchanged.
import numpy as np

class Tensor:
    def __init__(self, data, _children=(), _op=''):
        self.data = np.asarray(data, dtype=np.float64)
        self.grad = np.zeros_like(self.data)
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op

    def __repr__(self):
        return f"Tensor(shape={self.data.shape}, op={self._op})"

    @staticmethod
    def _unbroadcast(grad, shape):
        while grad.ndim > len(shape):
            grad = grad.sum(axis=0)
        for i, s in enumerate(shape):
            if s == 1 and grad.shape[i] != 1:
                grad = grad.sum(axis=i, keepdims=True)
        return grad

    def __add__(self, other):
        other = other if isinstance(other, Tensor) else Tensor(other)
        out = Tensor(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad  += Tensor._unbroadcast(out.grad, self.data.shape)
            other.grad += Tensor._unbroadcast(out.grad, other.data.shape)
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Tensor) else Tensor(other)
        out = Tensor(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad  += Tensor._unbroadcast(out.grad * other.data, self.data.shape)
            other.grad += Tensor._unbroadcast(out.grad * self.data, other.data.shape)
        out._backward = _backward
        return out

    def matmul(self, other):
        out = Tensor(self.data @ other.data, (self, other), '@')
        def _backward():
            self.grad  += out.grad @ other.data.swapaxes(-1, -2)
            other.grad += self.data.swapaxes(-1, -2) @ out.grad
        out._backward = _backward
        return out

    def sum(self, axis=None, keepdims=False):
        out = Tensor(self.data.sum(axis=axis, keepdims=keepdims), (self,), 'sum')
        def _backward():
            grad = out.grad
            if not keepdims:
                if axis is None:
                    self.grad += np.ones_like(self.data) * grad
                    return
                ax = (axis,) if isinstance(axis, int) else axis
                for a in sorted(ax):
                    grad = np.expand_dims(grad, a)
            self.grad += np.broadcast_to(grad, self.data.shape)
        out._backward = _backward
        return out

    def relu(self):
        out = Tensor(np.maximum(0, self.data), (self,), 'relu')
        def _backward():
            self.grad += (self.data > 0) * out.grad
        out._backward = _backward
        return out

    def reshape(self, *shape):
        out = Tensor(self.data.reshape(*shape), (self,), 'reshape')
        def _backward():
            self.grad += out.grad.reshape(self.data.shape)
        out._backward = _backward
        return out

    def __getitem__(self, idx):
        out = Tensor(self.data[idx], (self,), 'getitem')
        def _backward():
            g = np.zeros_like(self.data)
            g[idx] += out.grad
            self.grad += g
        out._backward = _backward
        return out

    def pad2d(self, pad):
        out_data = np.pad(self.data, ((0,0),(0,0),(pad,pad),(pad,pad)))
        out = Tensor(out_data, (self,), 'pad2d')
        def _backward():
            H, W = self.data.shape[2], self.data.shape[3]
            self.grad += out.grad[:, :, pad:pad+H, pad:pad+W]
        out._backward = _backward
        return out

    def transpose(self, *axes):
        out = Tensor(self.data.transpose(*axes), (self,), 'transpose')
        def _backward():
            inv = np.argsort(axes)
            self.grad += out.grad.transpose(*inv)
        out._backward = _backward
        return out

    @staticmethod
    def stack(tensors, axis=0):
        out = Tensor(np.stack([t.data for t in tensors], axis=axis), tuple(tensors), 'stack')
        def _backward():
            grads = np.split(out.grad, len(tensors), axis=axis)
            for t, g in zip(tensors, grads):
                t.grad += g.reshape(t.data.shape)
        out._backward = _backward
        return out

    def backward(self):
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build(child)
                topo.append(v)
        build(self)
        self.grad = np.ones_like(self.data)
        for v in reversed(topo):
            v._backward()

    # ---- new in this module ----
    # Three arithmetic conveniences, then two FUSED ops (softmax, layernorm)
    # whose backward is hand-derived as one vectorized formula rather than
    # composed from add/mul/exp/sum. Lesson 4 derives both formulas from
    # scratch and gradchecks them before either is trusted.

    def __neg__(self):
        return self * -1.0

    def __sub__(self, other):
        other = other if isinstance(other, Tensor) else Tensor(other)
        return self + (-other)

    def __radd__(self, other):
        return self + other

    def __rmul__(self, other):
        return self * other

    def __truediv__(self, other):
        other = other if isinstance(other, Tensor) else Tensor(other)
        out = Tensor(self.data / other.data, (self, other), '/')
        def _backward():
            self.grad  += Tensor._unbroadcast(out.grad / other.data, self.data.shape)
            other.grad += Tensor._unbroadcast(-out.grad * self.data / (other.data ** 2), other.data.shape)
        out._backward = _backward
        return out

    def mean(self, axis=None, keepdims=False):
        if axis is None:
            n = self.data.size
        else:
            ax = (axis,) if isinstance(axis, int) else axis
            n = 1
            for a in ax:
                n *= self.data.shape[a]
        return self.sum(axis=axis, keepdims=keepdims) * (1.0 / n)

    def exp(self):
        out = Tensor(np.exp(self.data), (self,), 'exp')
        def _backward():
            self.grad += out.data * out.grad     # d(e^x)/dx = e^x = the output itself
        out._backward = _backward
        return out

    def softmax(self, axis=-1):
        """Forward subtracts the row max directly on .data -- a constant
        shift that leaves the true softmax unchanged (AIE-202-M04 Lesson 4),
        so it needs no gradient path of its own. Backward is the softmax
        Jacobian-vector product, in one vectorized expression:
            dL/dx_i = s_i * (dL/ds_i - sum_j s_j * dL/ds_j)"""
        z = self.data - self.data.max(axis=axis, keepdims=True)
        e = np.exp(z)
        s = e / e.sum(axis=axis, keepdims=True)
        out = Tensor(s, (self,), 'softmax')
        def _backward():
            g = out.grad
            dot = (g * s).sum(axis=axis, keepdims=True)
            self.grad += s * (g - dot)
        out._backward = _backward
        return out

    def layernorm(self, gamma, beta, axis=-1, eps=1e-5):
        """Normalize-then-learnable-rescale, M02's BatchNorm1d contract,
        reduced over the FEATURE axis of each token independently -- not
        over the batch axis. gamma, beta: Tensor, shape (d_model,)."""
        x = self.data
        mu = x.mean(axis=axis, keepdims=True)
        xc = x - mu
        var = (xc ** 2).mean(axis=axis, keepdims=True)
        std_inv = 1.0 / np.sqrt(var + eps)
        xhat = xc * std_inv
        out_data = xhat * gamma.data + beta.data
        out = Tensor(out_data, (self, gamma, beta), 'layernorm')
        N = x.shape[axis]
        def _backward():
            g = out.grad
            gamma.grad += Tensor._unbroadcast(g * xhat, gamma.data.shape)
            beta.grad  += Tensor._unbroadcast(g, beta.data.shape)
            dxhat = g * gamma.data
            term1 = N * dxhat
            term2 = dxhat.sum(axis=axis, keepdims=True)
            term3 = xhat * (dxhat * xhat).sum(axis=axis, keepdims=True)
            self.grad += (std_inv / N) * (term1 - term2 - term3)
        out._backward = _backward
        return out
```

Notice what a **fused** op is, precisely, because Lesson 4 makes you defend the choice: `softmax` could have been written as `(self - self.max(...)).exp() / (self - self.max(...)).exp().sum(...)`, four composed primitives, each already gradchecked individually. This module instead writes softmax's *entire* forward-and-backward as one method, with a backward formula derived by hand from the softmax Jacobian rather than assembled from smaller pieces. Both approaches compute the same function. The fused version is what production frameworks actually ship (a fused softmax kernel, a fused LayerNorm kernel) for speed and numerical stability — and building one, once, by hand, means you can no longer be told "it's a fused kernel, don't worry about it" without knowing exactly what that sentence is asking you to trust.

**`gradcheck.py` — M01 Lesson 4's central-difference check, generalized to array-valued `Tensor` parameters.** M01 built gradcheck for a single scalar `Value`; M02/M03's `Tensor` work never needed its own version because M03's CNN labs checked shapes and forward values, not full end-to-end gradients. This module's fused ops and multi-block compositions make a real gradcheck non-negotiable again, so here it is, generalized once, used for the rest of this module and every lab below:

```python
# gradcheck.py
import numpy as np

def gradcheck(f, tensors, eps=1e-6):
    """f(tensors) -> scalar Tensor. Checks every element of every tensor's
    analytic grad against a central-difference numeric grad. Returns
    (max_rel_err, (tensor_index, element_index)) for the worst element."""
    for t in tensors:
        t.grad = np.zeros_like(t.data)
    out = f(tensors)
    out.backward()
    max_rel_err = 0.0
    worst = None
    for ti, t in enumerate(tensors):
        analytic = t.grad.copy()
        it = np.nditer(t.data, flags=['multi_index'])
        numeric = np.zeros_like(t.data)
        for _ in it:
            idx = it.multi_index
            orig = t.data[idx]
            t.data[idx] = orig + eps
            f_plus = f(tensors).data
            t.data[idx] = orig - eps
            f_minus = f(tensors).data
            t.data[idx] = orig
            numeric[idx] = (f_plus - f_minus) / (2 * eps)
        rel = np.abs(analytic - numeric) / np.maximum(np.maximum(np.abs(analytic), np.abs(numeric)), 1e-8)
        m = rel.max()
        if m > max_rel_err:
            max_rel_err = m
            worst = (ti, np.unravel_index(np.argmax(rel), rel.shape))
    return max_rel_err, worst
```

Every `gradcheck(...)` call in this module's Lessons and Labs is this exact function — perturb one element of `.data` at a time, in place, run the *entire* forward pass fresh, central-difference it against the analytic `.grad` accumulated by one `.backward()` call. It is more expensive than M01's version (one `f(tensors)` call per element of every tensor being checked) and that cost is precisely why it is used to spot-check specific compositions in this module's labs, not run on every training step.

## Lessons

### Lesson 1 — Why position must be injected: self-attention is permutation equivariant

M04 Lesson 3 built attention as a lookup: a query compared against every key, softmax-weighted, summed into a context vector. Nothing in that mechanism — dot products, softmax, a weighted sum — refers to *where* a token sits in the sequence. This lesson makes that claim precise and testable, not just plausible: **self-attention, with no positional information injected, is a permutation-equivariant function of its input.** Permute the input tokens and the output tokens permute identically — the function has no way to know `token 0` came first.

**The claim, proven by construction, not asserted.** Self-attention on a sequence `X = [x_0, ..., x_{T-1}]` computes `Q = XW_q`, `K = XW_k`, `V = XW_v`, then `Attention(Q,K,V) = softmax(QK^T/√d_k)V` — every one of those operations (matrix multiply, softmax along a fixed axis, another matrix multiply) treats the sequence axis as an unordered set of rows, not an ordered list. Permute the rows of `X` by some permutation `π`, and every downstream quantity permutes by that same `π`: `Q`'s rows permute, `K`'s rows permute, the score matrix `QK^T` has both its rows *and* columns permuted (since both `Q` and `K` came from the same permuted `X`), softmax along the last axis is invariant to how the *other* axis is ordered, and the final weighted sum's rows permute along with everything else. The formal statement is `Attention(πX) = π · Attention(X)` for any permutation `π` — attention **commutes** with reordering the input.

**Worked example — measured, not argued.** Six tokens, `d_model=6`, random `Wq`/`Wk`/`Wv` (`seed=2`). Run self-attention on the sequence as-is, and again on the sequence permuted by `π = [2,0,3,1,5,4]`:

```python
out_orig       = attention(X)                     # (6, 6)
out_perm_input = attention(X[perm])                # attention on the REORDERED input
out_perm_of_output = out_orig[perm]                # the ORIGINAL output, reordered after the fact
```

Measured: `max |out_perm_input - out_perm_of_output| = 4.44e-16` — floating-point zero. Attending to a reordered sequence and reordering the attended output afterward produce **the same numbers**. The attention mechanism, run exactly as M04 built it, genuinely cannot distinguish `[cat, sat, mat]` from `[mat, cat, sat]` — it produces the identical multiset of outputs, just relabeled by whichever permutation you handed it.

**The fix — inject a fact about position directly into the input, before attention ever runs.** Vaswani et al. add a fixed, non-learned vector `PE(pos)` to each token's embedding, where every dimension is a sine or cosine at a different frequency:

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

`pos` is the token's index in the sequence; `i` indexes the pair of dimensions. Adjacent dimension-pairs cycle through sine and cosine at geometrically decreasing frequencies as `i` grows — dimension pair 0 oscillates fastest (period `2π`), the last pair oscillates slowest (period `2π · 10000`). Adding `PE(pos)` to `x_pos` before projecting to `Q`/`K`/`V` means the query and key vectors now carry a fingerprint of *where* the token sits, not just *what* it is.

**Worked example — the same permutation test, with PE added, on the identical `X`, `Wq`, `Wk`, `Wv`.**

```python
def run_with_pe(Xnp, pe): 
    Xt = Tensor(Xnp) + Tensor(pe)      # pe: fixed sinusoidal table, sliced to seq_len
    ...attention as before...
```

Measured: `max |out_perm_input - out_perm_of_output| = 0.6015` — no longer floating-point zero, **six hundred million times larger** than the no-PE case. Order now measurably matters. The `PE` table is fixed to *position*, not to token identity, so permuting which tokens sit where changes which positional fingerprint each token receives — and the model's output changes correspondingly. This is the entire justification for positional encoding in one paired experiment: prove the mechanism is blind without it, then prove one line of code (`x + pe`) fixes it, on the same numbers.

**A second property, not required for correctness but load-bearing for what the model can learn: relative position is a fixed linear function of the encoding.** For any fixed offset `k`, `PE(pos+k)` is a fixed rotation matrix applied to `PE(pos)`, independent of `pos` itself — a consequence of the angle-addition identities for sine and cosine. For dimension pair `(0,1)` (`θ = 1/10000^0 = 1`) and offset `k=5`:

```
M = [[cos(5), sin(5)], [-sin(5), cos(5)]]
predicted PE(pos+5)[0:2] = M @ PE(pos)[0:2]
```

Measured at `pos ∈ {0, 3, 10, 22}`: predicted and actual agree to `1e-9` at every one of the four positions — e.g. at `pos=3`: predicted `[-0.9589, 0.2837]`, actual `[-0.9589, 0.2837]`, exact to the printed digits. Because `M` depends only on `k`, not on `pos`, a linear layer *could* in principle learn to attend by relative offset directly from the sinusoidal encoding — this is the property the paper cites as the reason for choosing sine/cosine over, say, a raw integer or a one-hot position index.

**Named misconception 1 — "attention already knows the order of tokens, because it processes them in sequence, one after another."** Refuted directly by the measured `4.44e-16` permutation-equivariance result. Attention does not process tokens "in sequence" the way an RNN does — every `Q`/`K`/`V` for every position is computed independently and in parallel, and the softmax-weighted sum treats the set of keys as exactly that, a set. The word "sequence" describing the *input data structure* (a Python list, an array with a leading time axis) is doing no work inside the attention computation itself unless something — positional encoding, here — puts order-information into the numbers.

**Named misconception 2 — "the sinusoidal formula is an arbitrary historical choice; any encoding that gives each position a distinct vector would work identically."** Partially true and importantly incomplete. Any *injective* encoding (a distinct vector per position — a learned embedding table would also satisfy this) breaks the exact `4.44e-16` permutation-equivariance result the same way sinusoidal PE does; the paper itself reports learned positional embeddings perform comparably at the sequence lengths it tested. But the two are **not identical** in what they buy you: a learned embedding table has one row per position seen during training and produces nonsense (or requires interpolation) for a position past the longest training sequence, while the sinusoidal formula is a closed-form function of `pos` that extrapolates to *any* sequence length, including ones longer than anything seen in training — plus the relative-position linear-rotation property measured above, which a learned table has no reason to exhibit at all. "Any distinct-per-position vector works the same" collapses a real design tradeoff (extrapolation and relative-position structure vs. purely empirical flexibility) into "doesn't matter, arbitrary" — it isn't arbitrary, it's a specific bet the paper's authors made and stated their reasons for.

### Lesson 2 — Multi-head self-attention: every position as a query, split into parallel subspaces

M04's `TinyAttention` formed exactly **one** query, from the sequence's last token, and attended it against every key. This lesson makes two changes at once, and it is worth separating them cleanly because they are independent ideas that happen to ship together. **Change one: every position forms its own query**, not just the last — this is what "self-attention" actually means, and it is the direct generalization M04 Lesson 3's own closing note promised. **Change two: the projection is split into `h` parallel, narrower subspaces ("heads")**, each computing its own attention independently, before the results are concatenated and mixed back together by one more linear layer.

**Self-attention, full: every position queries every position.** With `X` shape `(T, d_model)`, project once: `Q = XW_q`, `K = XW_k`, `V = XW_v`, each `(T, d_model)`. Every *row* of `Q` is a separate query — `Attention(Q,K,V) = softmax(QK^T/√d_k)V` now computes a full `(T, T)` score matrix (row `t` = query `t`'s scores against every key), softmaxed row-wise, producing a `(T, d_model)` context — one context vector *per position*, not one for the whole sequence. This is the generalization Lab M04-B's own Elle acceleration note named as the next step, now built for real.

**Multi-head: same total budget, split into parallel narrower views, not h separate forward passes.** Instead of one `(T, d_model) → (T, d_model)` attention, split each of `Q`, `K`, `V` along the feature axis into `h` heads of width `d_k = d_model / h`, run scaled dot-product attention **independently and in parallel** within each head, then concatenate the `h` outputs back to `(T, d_model)` and mix them with one final linear layer `W_o`:

```python
def split_heads(x, h):          # (T, d_model) -> (h, T, d_k)
    T, d_model = x.data.shape
    d_k = d_model // h
    return x.reshape(T, h, d_k).transpose(1, 0, 2)

def merge_heads(x):             # (h, T, d_k) -> (T, d_model)
    h, T, d_k = x.data.shape
    return x.transpose(1, 0, 2).reshape(T, h * d_k)

def multi_head_attention(x, Wq, Wk, Wv, Wo, h):
    Q, K, V = x.matmul(Wq), x.matmul(Wk), x.matmul(Wv)
    out_h = scaled_dot_product_attention(split_heads(Q, h), split_heads(K, h), split_heads(V, h))
    return merge_heads(out_h).matmul(Wo)
```

`split_heads` and `merge_heads` are exact inverses of each other — `reshape` then `transpose`, undone by `transpose` then `reshape` — and neither is a new primitive; both are the M03 `Tensor.reshape`/`Tensor.transpose` you already trust, called on a new axis arrangement. `scaled_dot_product_attention` runs on `(h, T, d_k)` tensors and NumPy's batched-matmul semantics apply `Q @ K^T` independently across the leading `h` axis in one call — `h` heads computed as one vectorized array operation, never a Python `for` loop over heads.

**Worked example — `seq=3`, `d_model=8`, `h=2` (so `d_k=4`), `seed=1`.**

```
output shape: (3, 8)
output:
 [[ 1.552  -2.0811  0.3111 -0.3142 -0.5068  0.7555 -0.2064 -0.3122]
  [ 0.8753 -0.9377  0.0839 -0.0352 -0.386   0.1549 -0.4315 -0.141 ]
  [-0.555  -0.5055 -0.691   0.9388 -0.9111 -0.7826 -1.6217 -0.5035]]
multi-head self-attention gradcheck max rel err: 4.000399930992288e-07
```

The output shape is `(3, 8)` — identical to the input shape `(T, d_model)`, regardless of `h`. This is what makes stacking blocks (Lesson 4) possible at all: a transformer block's output has the exact same shape as its input, so blocks compose without any reshaping glue between them.

**Worked example — the budget is fixed, only the split changes, `d_model=32`:**

```
h=1:  d_k = 32       h=2:  d_k = 16       h=4:  d_k = 8       h=8:  d_k = 4       h=16: d_k = 2
```

The *total* number of `Q`/`K`/`V`/`O` parameters (`4 × d_model × d_model`) does not change as `h` changes — only how that fixed budget is partitioned into parallel subspaces. `h=1` is exactly M04-B's single-head self-attention extended to every position as a query; `h=32` would give each head a single scalar dimension to work with, degenerate at the low end. The paper's own choice (`d_model=512`, `h=8`, `d_k=64`) sits comfortably in between.

**Named misconception 1 — "more attention heads means more parameters, and therefore more capacity devoted to the attention computation."** Refuted directly by the `d_k` table: `Wq`, `Wk`, `Wv`, `Wo` are each `(d_model, d_model)` regardless of `h` — the parameter count of a multi-head attention layer is **independent of the number of heads**, for a fixed `d_model`. What changes is not *how much* is computed, but *how it's partitioned*: each head sees a narrower `d_k`-dimensional slice of the representation and computes its own independent attention pattern within that slice, before `W_o` mixes the `h` results back together. More heads is a change in the *shape* of the computation (more, narrower parallel views), not its total size.

**Named misconception 2 — "multi-head attention requires computing attention h separate times, once per head, in a loop."** Refuted directly by the code: `split_heads` reshapes `(T, d_model)` into `(h, T, d_k)` **once**, and `scaled_dot_product_attention` calls `Q.matmul(K.transpose(0,2,1))` **once** — NumPy's batched matmul (and the `Tensor.matmul` wrapper around it, unmodified since M03) applies the `(T,d_k) @ (d_k,T)` operation independently across the leading `h` axis as a single vectorized array call. There is no Python-level loop over heads anywhere in this lesson's implementation, and there does not need to be — "parallel heads" describes the *mathematical* structure (independent subspaces), not a literal `for h in range(num_heads)` in the code that computes them.

### Lesson 3 — Layer norm placement and the residual stream

A transformer **block** wraps each of its two sublayers — multi-head self-attention, then the feed-forward network Lesson 4 builds — in a residual connection followed by layer normalization: `x = LayerNorm(x + Sublayer(x))`. This lesson is about why both halves of that sentence — the `x +` and the `LayerNorm`, and specifically their *order* — are load-bearing, not stylistic.

**The residual connection: an identity path home, exactly the fix M02's whole first module was missing.** Stack `N` transformer blocks and you have re-created, structurally, the deep-network gradient problem M02 Lesson 1 opened the entire course with: a signal has to survive a trip through `N` sublayers to reach the earliest layer's gradient. A **residual connection** — `x + Sublayer(x)` instead of just `Sublayer(x)` — means that even if `Sublayer`'s own local Jacobian is poorly conditioned at some layer, the `+x` term guarantees the identity path's gradient (`d(x+Sublayer(x))/dx ⊇ 1`, from the `+x` alone) is always available as a lower bound. This is the same insight He et al.'s ResNet applied to deep CNNs, applied here to deep transformer stacks — and it is a direct answer to the exact failure mode M02 diagnosed and M04 re-diagnosed on a different axis (time instead of depth). A residual connection doesn't guarantee a healthy gradient; it guarantees a **floor**.

**LayerNorm's axis, precisely, because "just BatchNorm renamed" is the trap.** `LayerNorm(x)` normalizes **each token's own feature vector independently** — for a `(T, d_model)` sequence, it computes `mean` and `variance` **along the `d_model` axis, separately for every one of the `T` rows** — then rescales with a learned `gamma`/`beta`, shape `(d_model,)`, shared across every position (weight sharing again, the same story as M04's `Whh` and M03's convolution kernel). `BatchNorm1d`, M02's version, normalizes along the **batch** axis instead — every feature's statistics computed across the examples in a minibatch, not across a single example's own features. The two operations share a formula (`(x - mean) / sqrt(var + eps) * gamma + beta`) and differ *only* in which axis `mean`/`var` are computed over — and that one difference has a large practical consequence: LayerNorm's statistics for a given token do not depend on which other tokens happen to be in the same batch or the same sequence, which matters enormously for sequence models where batch composition is somewhat arbitrary and sequence length varies example to example.

**Worked example — LayerNorm actually produces what it claims to, measured on deliberately off-scale input.** Feed a single encoder block an input scaled and shifted far from a nice unit distribution (`std=5`, `mean=3`) and check every token's post-block statistics:

```python
x = Tensor(rng.randn(5, 16) * 5.0 + 3.0)     # deliberately off-scale
out = block(x)
per_token_mean = out.data.mean(axis=-1)      # per TOKEN, along d_model
per_token_var  = out.data.var(axis=-1)
```

Measured: every one of the 5 tokens' post-block feature vectors has `mean ≈ 0.0` (within `1e-6`) and `variance ≈ 1.0` (within `1e-3`) — regardless of how off-scale the *input* was. This is LayerNorm doing exactly its contract, verified, not assumed: whatever scale the residual stream drifts to internally, every token gets renormalized to the same footing before the next sublayer sees it.

**Placement: `LayerNorm(x + Sublayer(x))` — "Post-LN," the paper's own choice — versus `x + Sublayer(LayerNorm(x))` — "Pre-LN," now the more common default.** Both wrap a residual around each sublayer; they differ in whether normalization happens *before* the sublayer runs (Pre-LN) or *after* the residual sum is formed (Post-LN). Vaswani et al. 2017 shipped Post-LN. This module builds Post-LN — it is what "from the paper" means concretely — and measures, rather than asserts, how it behaves differently from the now-more-common alternative.

**Worked example — mean `|gradient|` reaching the input embedding, as a stack of blocks gets deeper, 5-seed mean, random initialization, no training:**

| depth (blocks) | Post-LN mean `\|grad\|` | Pre-LN mean `\|grad\|` |
|---|---|---|
| 1 | 0.3298 | 0.4301 |
| 2 | 0.4496 | 0.6433 |
| 4 | 0.7016 | 1.2008 |
| 8 | 0.4543 | 1.5826 |
| 16 | 0.1368 | 2.0247 |
| 32 | 0.1137 | 3.7867 |

Both curves start comparably (`depth=1`: `0.33` vs. `0.43`). By `depth=32`, they have gone in **opposite directions**: Post-LN's gradient reaching the input has *shrunk* to roughly a sixth of its `depth=4` peak (`0.70 → 0.11`), while Pre-LN's has *grown* more than threefold over the same range (`1.20 → 3.79`) and grown monotonically at every depth measured. This is not folklore recited from a paper — it is this module's own numbers, and it is the concrete, measured version of a documented finding in the field's own later literature (Xiong et al. 2020, "On Layer Normalization in the Transformer Architecture"): Post-LN transformers are harder to train at depth without a learning-rate warmup schedule specifically because their gradient behavior at initialization is less well-behaved than Pre-LN's. You built the architecture the paper shipped; this table is what you now know about the *cost* of that specific choice, measured on your own engine, not read secondhand.

**Named misconception 1 — "LayerNorm and BatchNorm are the same operation, just renamed for sequence models."** Refuted by the axis argument above: the *formula* is identical, but `BatchNorm1d` reduces over the batch axis and `LayerNorm` reduces over the feature axis — different axis, different statistics, different failure modes (BatchNorm's statistics depend on batch composition and behave differently at train vs. eval time — M02's own material; LayerNorm's do not, since they're computed per-example). Treating them as interchangeable erases the exact design reason sequence models moved to LayerNorm in the first place: variable-length sequences and small or single-example batches make batch-axis statistics unstable or ill-defined in a way that per-token feature statistics never are.

**Named misconception 2 — "Post-LN versus Pre-LN is an implementation detail that doesn't meaningfully affect training."** Directly refuted by the depth table: at `depth=32`, the two placements' gradient-to-input measurements differ by more than **33x**, and they are trending in *opposite* directions as depth increases, not just different magnitudes of the same trend. This is not a rounding-level implementation choice — it is the difference between a quantity that shrinks with depth and one that grows with depth, on the identical block-building-blocks, differing only in whether `LayerNorm` sits before or after the residual sum.

### Lesson 4 — Assembling the block: the feed-forward sublayer, and gradchecking the whole thing

The paper's encoder block has exactly two sublayers wrapped in `LayerNorm(x + Sublayer(x))`: multi-head self-attention (Lesson 2), and a position-wise feed-forward network. This lesson builds the second sublayer, assembles the full block, stacks it, and gradchecks the entire thing end to end — the same discipline M01 Lesson 4 established for a five-node graph, now applied to a multi-block transformer.

**The feed-forward sublayer: two linear layers with a ReLU between them, applied to every position with the SAME two weight matrices.**

```
FFN(x) = max(0, xW1 + b1)W2 + b2
```

`W1` is `(d_model, d_ff)` (usually `d_ff > d_model`, an expansion — the paper uses `d_ff = 4 × d_model`); `W2` projects back down to `(d_ff, d_model)`. Applied to a `(T, d_model)` sequence, `x @ W1` broadcasts `W1` across every one of the `T` positions **identically** — this is, once again, the exact weight-sharing story that has run through this entire course on a different axis every time: M03's convolution kernel reused across every spatial location, M04's `Whh` reused across every timestep, and now `W1`/`W2` reused across every sequence position. The FFN does not "know" which position it's processing; it is the same two-layer network, called once per token, with the identical weights.

**Assembling the block — every piece from Lessons 1-3, composed exactly as the paper specifies:**

```python
class EncoderBlock:
    def __init__(self, d_model, num_heads, d_ff, seed=0):
        self.mhsa = MultiHeadSelfAttention(d_model, num_heads, seed=seed)
        self.ffn = FeedForward(d_model, d_ff, seed=seed + 1)
        self.ln1_g, self.ln1_b = Tensor(np.ones(d_model)), Tensor(np.zeros(d_model))
        self.ln2_g, self.ln2_b = Tensor(np.ones(d_model)), Tensor(np.zeros(d_model))

    def __call__(self, x):
        attn_out = self.mhsa(x)
        x = (x + attn_out).layernorm(self.ln1_g, self.ln1_b)   # Add & Norm, sublayer 1
        ff_out = self.ffn(x)
        x = (x + ff_out).layernorm(self.ln2_g, self.ln2_b)     # Add & Norm, sublayer 2
        return x
```

A full `TransformerEncoder` is this block stacked `N` times, with positional encoding added once at the input, followed (for this module's toy task) by a mean-pool over positions and one linear readout to a scalar.

**Worked example — the shape trace, `seq=6`, `d_model=16`, `num_heads=4`, `d_ff=32`, 2 stacked blocks:**

```
input + PE:        (6, 16)
after block 1:      (6, 16)
after block 2:      (6, 16)
pooled + readout:  scalar = 0.1859
```

Every block's output has the **identical shape** as its input — `(T, d_model)` in, `(T, d_model)` out, at every one of the `N` blocks. This is Lesson 2's shape-invariance property, and it is what makes "stack the block `N` times" a one-line loop rather than `N` bespoke layer definitions.

**Worked example — the gradcheck, end to end, input embedding through both blocks and every parameter, against finite differences.** A subtlety worth naming precisely, because it is a real engineering fact about gradchecking deep composed graphs, not this module's engine being unreliable: at `eps=1e-6` (the value every prior module used for a single primitive), a two-block encoder's gradcheck reports `max rel err = 1.31e-4` — noticeably worse than a single op's typical `~1e-8`. At `eps=1e-5`, the same check reports `2.73e-5` — *better*, not worse. This is the classic central-difference tradeoff: too-small an `eps` loses precision to floating-point cancellation once a function is composed through enough operations (dozens, here, across two full blocks); too-large an `eps` loses precision to truncation error instead. The fix is not a looser tolerance for a shakier engine — it is a **calibrated `eps`** for a deeper composed function, the same numerical-methods judgment call every finite-difference method requires. At `eps=1e-5`:

```
full encoder (PE + 2 blocks + readout) gradcheck max rel err: 2.73e-05
```

Comfortably under this module's `1e-3` tolerance — the entire block, every attention projection, every FFN weight, both LayerNorms' gamma and beta, and the input embedding itself, all confirmed against finite differences in one check.

**Named misconception 1 — "if a gradcheck shows exactly zero gradient reaching a parameter, the backward pass must be broken."** This module's own engine surfaced a real, verified counterexample worth carrying forward as a standing caution: gradcheck a single block's output summed directly (`block(x).sum()`, with `LayerNorm`'s `gamma` initialized to all-ones and `beta` to all-zeros, the standard initialization) and the analytic gradient reaching `x`, every attention weight, and even the *first* LayerNorm's own `gamma`/`beta` is **exactly zero** — not small, not vanishing, exactly zero, to `1e-16`. The reason is algebraic, not a bug: a unit-gamma LayerNorm's output is, by construction, mean-zero along the feature axis for *every* token, for *any* input — so summing it is an identity that always returns `≈0`, and the true derivative of a function that is identically zero everywhere is, correctly, zero everywhere. (Only the *final* LayerNorm's own `gamma`/`beta` — which appear as direct multiplicative/additive terms inside the very operation being summed, not upstream of it — receive real gradient: measured `4.43` and `5.00` respectively, the latter exactly `T=5`, the sequence length, as `d(sum)/d(beta_j) = T` predicts exactly.) The lesson is not "gradcheck is untrustworthy near LayerNorm" — it is "know what your test function's *true* gradient should be before you run gradcheck, or a mathematically correct zero and a genuine bug look identical." Every gradcheck in this module's own labs uses a real linear readout specifically to avoid this trap — never raw `.sum()` after a unit-gamma LayerNorm.

**Named misconception 2 — "the feed-forward sublayer needs a different set of weights at each position, since different positions are attending to different things by the time they reach it."** Refuted directly by the code: `FeedForward.__init__` allocates exactly one `W1`, `b1`, `W2`, `b2`, and `EncoderBlock.__call__` calls `self.ffn(x)` **once**, on the full `(T, d_model)` tensor — the same four weight tensors process every position identically, exactly as `matvec(Whh, h)` in M04 reused the same `Whh` at every timestep. That the FFN's *input* differs from position to position (because attention has already mixed in different context at each position) does not mean the FFN's *weights* differ — the function is the same at every position; only its argument changes. This is worth stating precisely because it is easy to conflate "the output looks different at each position" with "a different function computed the output at each position" — they are not the same claim, and only the first one is true here.

    pos = np.arange(seq_len)[:, None].astype(np.float64)
    i = np.arange(d_model)[None, :].astype(np.float64)

```python
# lab_c_solution.py
import numpy as np
from tensor import Tensor
from lab_a_solution import sinusoidal_positional_encoding
from lab_b_solution import MultiHeadSelfAttention


class FeedForward:
    def __init__(self, d_model, d_ff, seed=0):
        rng = np.random.RandomState(seed)
        std1 = 1.0 / np.sqrt(d_model)
        std2 = 1.0 / np.sqrt(d_ff)
        self.W1 = Tensor(rng.randn(d_model, d_ff) * std1)
        self.b1 = Tensor(np.zeros(d_ff))
        self.W2 = Tensor(rng.randn(d_ff, d_model) * std2)
        self.b2 = Tensor(np.zeros(d_model))

    def __call__(self, x):
        return (x.matmul(self.W1) + self.b1).relu().matmul(self.W2) + self.b2

    def parameters(self):
        return [self.W1, self.b1, self.W2, self.b2]


class EncoderBlock:
    """POST-LN, exactly as Vaswani et al. 2017 Sec. 3.1: LayerNorm(x + Sublayer(x))."""
    def __init__(self, d_model, num_heads, d_ff, seed=0):
        self.mhsa = MultiHeadSelfAttention(d_model, num_heads, seed=seed)
        self.ffn = FeedForward(d_model, d_ff, seed=seed + 1)
        self.ln1_g = Tensor(np.ones(d_model)); self.ln1_b = Tensor(np.zeros(d_model))
        self.ln2_g = Tensor(np.ones(d_model)); self.ln2_b = Tensor(np.zeros(d_model))

    def __call__(self, x):
        attn_out = self.mhsa(x)
        x = (x + attn_out).layernorm(self.ln1_g, self.ln1_b)
        ff_out = self.ffn(x)
        x = (x + ff_out).layernorm(self.ln2_g, self.ln2_b)
        return x

    def parameters(self):
        return (self.mhsa.parameters() + self.ffn.parameters()
                + [self.ln1_g, self.ln1_b, self.ln2_g, self.ln2_b])


class TransformerEncoder:
    def __init__(self, d_model, num_heads, d_ff, num_blocks, seed=0):
        self.blocks = [EncoderBlock(d_model, num_heads, d_ff, seed=seed + 10 * i)
                        for i in range(num_blocks)]
        rng = np.random.RandomState(seed + 999)
        self.readout_w = Tensor(rng.randn(d_model) * (1.0 / np.sqrt(d_model)))
        self.d_model = d_model

    def __call__(self, x, return_hidden=False):
        seq_len = x.data.shape[0]
        pe = sinusoidal_positional_encoding(seq_len, self.d_model)
        h = x + Tensor(pe)
        hiddens = [h]
        for block in self.blocks:
            h = block(h)
            hiddens.append(h)
        pooled = h.mean(axis=0)                 # (d_model,)
        yhat = (pooled * self.readout_w).sum()   # scalar
        if return_hidden:
            return yhat, hiddens
        return yhat

    def parameters(self):
        ps = [self.readout_w]
        for block in self.blocks:
            ps += block.parameters()
        return ps
```

A learner mid-debugging on their own Lab M05-C build who sees a failing gradcheck and starts rewriting `layernorm`'s backward formula (which is correct) instead of first trying a larger `eps` is chasing the wrong variable. **Reroute:** before touching any backward-pass code, have them rerun the identical gradcheck at two or three different `eps` values (`1e-4`, `1e-5`, `1e-6`) and look for a U-shape in the error — if the error is *worse* at the smallest `eps`, that is evidence for floating-point cancellation, not a code bug, and the fix is a calibration change, not a rewrite.
- **Wall — Lesson 4's "zero gradient" misconception, hit live on the learner's own code, not just read about.** A learner who accidentally gradchecks their own block with a raw `.sum()` loss (rather than a proper readout) and sees every upstream gradient come back near-zero will very often conclude their entire attention/FFN/residual stack is broken. **Reroute:** do not let them start rewriting the block. Have them print the *forward* value of the loss first (it will be `≈0`, not merely small) and ask them to derive, on paper, whether a function that is identically zero for *every* input could possibly have a nonzero derivative anywhere — the algebra, not a debugger, is what resolves this one.
- **Signal — a learner whose Lab M05-A Predict item 3 correctly anticipates that different `(2i, 2i+1)` dimension pairs need *different* rotation matrices, unprompted, tying it to the `θ` term's dependence on `i`.** This is real transfer from Lesson 1's own worked derivation, not memorization — log `struggle-productive` territory resolved cleanly, and consider accelerating this learner past a second full walkthrough of the PE formula's derivation.
- **Accelerate — clean Lab M05-A and M05-B (correct Predicts, all tests passing on first attempt), especially a learner who names the PE-broadcast bug's likely category from the symptom alone in Lab M05-C's Predict, before seeing any source.** Such a learner has demonstrated the exact "symptom-first" diagnostic reasoning this module's Assessment grades directly — they can skip re-deriving `TransformerEncoder` from the Lab M05-C skeleton and instead be handed the completed reference implementation, spending the saved time extending it to a **causal mask** (restricting each position's attention to only earlier positions — the one mechanical piece separating an encoder block from a decoder block, and the piece M06's PyTorch-based generation work will need) and predicting, before building, which entries of the `(T,T)` score matrix should be set to `-∞` before the softmax, and why `-∞` specifically rather than `0`.

## Three-tier reading

Specific to this module's subject: the paper that ships as "the" architecture now underneath nearly everything downstream of it, and what building it from its own equations does and doesn't tell you about what it does.

- **Tier 1 — material ground.** "Attention Is All You Need" (Vaswani et al., 2017) is the paper this module builds, equation by equation: scaled dot-product attention (Eq. 1), multi-head attention as `h` parallel projections concatenated and mixed by `W^O` (Eq. 2, Sec. 3.2.2), the position-wise feed-forward network (Eq. 2 of Sec. 3.3), sinusoidal positional encoding (Eq. 3-4 of Sec. 3.5, including the paper's own stated reason for choosing it — extrapolation to sequence lengths not seen in training), and the residual-plus-LayerNorm wrapping of each sublayer (Sec. 3.1's own sentence, quoted in this module's Lesson 3, is `LayerNorm(x + Sublayer(x))` — Post-LN, exactly as this module builds it). Every one of these choices is documented, in the original paper, with the specific problem it was designed to solve — none of it is folklore, and this module's own Lessons re-derive or re-measure every one of the paper's central claims rather than asking you to take them on the authors' word.
- **Tier 2 — what the field suppresses.** "The transformer replaced recurrence because self-attention is a categorically better architecture" compresses a real, specific, measured tradeoff (M04's own numbers: attention's gradient-to-distance decay is roughly `2.97 million / 41 ≈ 72,000` times gentler than an RNN's, not zero) into an unqualified superiority claim the paper's own abstract does not make — Vaswani et al. present the transformer as faster to train (no sequential dependency across timesteps, so positions parallelize) and empirically better on the specific translation benchmarks tested, not as solving sequence modeling in general. The gap between "won on these benchmarks, trains faster" and "is simply the correct architecture for sequences" is exactly the gap this course's field-replication thread (Tier 1 of the course-level ethics arc) keeps returning to: the paper that displaced RNNs did so by a specific, measured margin, on specific tasks, in 2017 — and the field's retrospective narrative has, at times, smoothed a contingent, benchmark-specific victory into an inevitability it was not, at the time, guaranteed to be. This module's own Post-LN vs. Pre-LN numbers (Lesson 3) are a small, present-day echo of the same pattern: the paper's own architectural choice (Post-LN) turned out, empirically, three years later (Xiong et al., 2020), to have a specific, measurable training-stability cost the original paper did not flag — "the architecture from the paper" and "the architecture the field actually trains today" have already, quietly, diverged on a single load-bearing detail, and most implementations you will encounter outside this course default to the paper's *not*-quite-original choice without saying so.
- **Tier 3 — sit with this.** You have now built, from its own equations, on your own engine, gradchecked and shape-verified, the specific architecture that every large language model in current production is a scaled-up descendant of. You can explain every operation: why the `1/√d_k` scale exists, why positional encoding is necessary and what specific property the sinusoidal form buys over a learned table, why the residual connection is there and what floor it guarantees, why LayerNorm normalizes the axis it does and not the other one. This is real, complete, mechanism-level understanding of the *architecture* — more complete, if this module did its job, than most people who use these models professionally ever acquire. Here is the question the course's own ethics thread has been sharpening since M01, now aimed at its hardest target: the architecture you just built, scaled by roughly six orders of magnitude in parameter count and trained on a correspondingly larger fraction of the written internet, is the substrate underneath systems that display behaviors — in-context learning, chain-of-thought reasoning, emergent capabilities that appear discontinuously at certain scales — that no one derived from Eq. 1 through Eq. 4 of the paper you just implemented. You understand the mechanism completely. The mechanism, run at scale, produced things its own designers did not predict from the mechanism. If "I built it, I understand every line" is not sufficient grounds to predict what a sufficiently scaled version of your own working code will do — what *is* sufficient, and who is responsible for finding out before it ships, rather than after?
