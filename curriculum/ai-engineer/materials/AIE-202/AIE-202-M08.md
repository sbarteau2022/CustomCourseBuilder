## The harness this module builds, once, and reuses in every lab

Every lesson and lab below ablates a small `nn.Module` transformer encoder, built exactly the way M06 Lesson 4 idiomatically translated M05's from-scratch block into PyTorch — `MultiHeadSelfAttention` → `EncoderBlock` → a stack, with a sinusoidal positional encoding at the input (M05 Lesson 1) and `LayerNorm(x + Sublayer(x))`, Post-LN, exactly as M05 Lesson 3 built and measured it. Nothing about the *architecture* is new. What's new is that `MultiHeadSelfAttention.forward` accepts an **ablation spec** — which heads to intervene on, and what to replace their contribution with — and `EncoderBlock` accepts a **structural toggle** for its residual connection, so a lab can perform a real, reproducible intervention instead of describing one in prose.

```python
# ablation.py — the shared harness. Read once; every lab imports from it.
import numpy as np
import torch
import torch.nn as nn


def sinusoidal_pe(seq_len, d_model):
    """Identical formula to AIE-202-M05 Lesson 1 -- fixed, not learned."""
    pos = np.arange(seq_len)[:, None].astype(np.float64)
    i = np.arange(d_model)[None, :].astype(np.float64)
    angle_rates = 1.0 / np.power(10000.0, (2 * (i // 2)) / d_model)
    angles = pos * angle_rates
    pe = np.zeros((seq_len, d_model))
    pe[:, 0::2] = np.sin(angles[:, 0::2])
    pe[:, 1::2] = np.cos(angles[:, 1::2])
    return pe


class MultiHeadSelfAttention(nn.Module):
    """The M05/M06 math, plus one addition: forward() can intervene on one
    or more heads' CONTEXT vectors (the per-head output, before the Wo
    merge) and return that context alongside the block's normal output --
    so a lab can inspect or replace exactly one head's contribution without
    touching any other head's computation."""

    def __init__(self, d_model, num_heads):
        super().__init__()
        assert d_model % num_heads == 0
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads
        self.Wq = nn.Linear(d_model, d_model, bias=False)
        self.Wk = nn.Linear(d_model, d_model, bias=False)
        self.Wv = nn.Linear(d_model, d_model, bias=False)
        self.Wo = nn.Linear(d_model, d_model, bias=False)

    def _split(self, t, B, T):
        return t.view(B, T, self.num_heads, self.d_k).transpose(1, 2)   # (B,h,T,d_k)

    def forward(self, x, ablate_heads=None, replacement=None):
        """ablate_heads: list[int] of head indices to intervene on.
        replacement: None            -> ZERO-ablation (context set to 0)
                     Tensor (h, d_k) -> MEAN-ablation (context set to a
                                        fixed, precomputed per-head vector)
        Never mutates the live autograd graph -- ablation is an eval-time
        intervention, always run under torch.no_grad() in this module."""
        B, T, _ = x.shape
        Q = self._split(self.Wq(x), B, T)
        K = self._split(self.Wk(x), B, T)
        V = self._split(self.Wv(x), B, T)
        scores = Q @ K.transpose(-2, -1) / (self.d_k ** 0.5)
        weights = torch.softmax(scores, dim=-1)          # (B,h,T,T)
        context = weights @ V                              # (B,h,T,d_k)

        if ablate_heads:
            context = context.clone()
            for hidx in ablate_heads:
                if replacement is None:
                    context[:, hidx, :, :] = 0.0
                else:
                    context[:, hidx, :, :] = replacement[hidx]

        merged = context.transpose(1, 2).reshape(B, T, self.d_model)
        return self.Wo(merged), weights, context


class FeedForward(nn.Module):
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.fc1 = nn.Linear(d_model, d_ff)
        self.fc2 = nn.Linear(d_ff, d_model)

    def forward(self, x):
        return self.fc2(torch.relu(self.fc1(x)))


class EncoderBlock(nn.Module):
    def __init__(self, d_model, num_heads, d_ff):
        super().__init__()
        self.mhsa = MultiHeadSelfAttention(d_model, num_heads)
        self.ffn = FeedForward(d_model, d_ff)
        self.ln1 = nn.LayerNorm(d_model)
        self.ln2 = nn.LayerNorm(d_model)
        self.use_residual = True   # Lesson 3 / Lab C flips this, per block, post-hoc or at init

    def forward(self, x, ablate_heads=None, replacement=None):
        attn_out, weights, context = self.mhsa(x, ablate_heads, replacement)
        x = self.ln1(x + attn_out) if self.use_residual else self.ln1(attn_out)
        ff_out = self.ffn(x)
        x = self.ln2(x + ff_out) if self.use_residual else self.ln2(ff_out)
        return x, weights, context


class TinyEncoder(nn.Module):
    def __init__(self, vocab, d_model, num_heads, d_ff, seq_len, num_blocks=1):
        super().__init__()
        self.embed = nn.Embedding(vocab, d_model)
        pe = sinusoidal_pe(seq_len, d_model)
        self.register_buffer("pe", torch.tensor(pe, dtype=torch.float32))
        self.blocks = nn.ModuleList([EncoderBlock(d_model, num_heads, d_ff) for _ in range(num_blocks)])
        self.readout = nn.Linear(d_model, vocab)

    def forward(self, x, ablate_heads=None, replacement=None, block_idx=0):
        """ablate_heads/replacement apply to ONE block, `block_idx` (default
        the first) -- every other block runs un-ablated. Returns logits plus
        the ablated block's attention weights and per-head context, for
        inspection."""
        h = self.embed(x) + self.pe[: x.shape[1], :]
        weights_out, context_out = None, None
        for i, block in enumerate(self.blocks):
            if i == block_idx:
                h, weights_out, context_out = block(h, ablate_heads, replacement)
            else:
                h, _, _ = block(h)
        return self.readout(h), weights_out, context_out
```

Three design choices here are worth naming before Lesson 1, because each is itself a small methodological decision this module will keep returning to. **Ablation happens on `context`, not on `weights` or on a deleted parameter** — nothing about `Wq`, `Wk`, `Wv`, or `Wo` changes shape or value; the model's total capacity is untouched, and only this one head's *contribution to this one forward pass* is intervened on. **`context = context.clone()`** exists so ablation is never an accidental in-place corruption of a tensor something else still holds a reference to — the kind of aliasing bug M07's clinic would have made you diagnose the hard way. **`replacement` is `None` or a precomputed `(h, d_k)` tensor**, never recomputed per call — Lesson 1 makes precisely why that matters into a worked example.

## Lessons

### Lesson 1 — Ablation is an intervention, not an inspection, and "remove" is not one operation

An attention-weight heatmap, a gradient-norm plot, an activation histogram — every tool you have used so far in this course to *look at* a trained network is an observation: it tells you what the network did on the inputs you fed it. **Ablation is different in kind, not just in tooling.** It answers a counterfactual: not "what did this component do," but "what would the model's output have been if this component's contribution had been different, everything else held fixed, on this exact input." That is Judea Pearl's intervention rung of the causal ladder, not the association rung — and the entire discipline of this module rests on that distinction being real, not rhetorical. A component can correlate perfectly with an outcome (its activation is large exactly when the model is about to get the answer right) and still not be the thing causing that outcome — some *other* component might be doing the causing, and this one's activation might just be a downstream echo. Ablation is how you tell the difference: intervene, don't just watch.

**"Remove a head" is at least two different interventions, and they can disagree.** Concretely: **zero-ablation** sets a head's context vector to the zero vector at every position, in every example, for the rest of the forward pass. **Mean-ablation** replaces it instead with that head's own *average* context vector, computed once over a clean batch, held fixed. Both are legitimate, both appear in the interpretability literature, and they are answering subtly different questions: zero-ablation asks "what if this head contributed *nothing*," mean-ablation asks "what if this head contributed only its *typical, information-free* output, but the downstream layers still saw an in-distribution value to work with." The difference matters because a trained network's downstream weights were never shown a zero vector for that head during training (unless zero happens to already be a value that head produces) — feeding one at evaluation time is *also* an out-of-distribution intervention, on top of whatever "removing the head's information" was supposed to test.

**Worked example — the same four heads, ablated two ways, on a task built to need exactly one precise attention pattern.** A one-block, 4-head, `d_model=32` encoder trained on a synthetic **shift-2** task: given a length-10 sequence of tokens from an 8-token vocabulary, predict `target[i] = input[i-2]` for every position `i ≥ 2` (positions 0-1 have no valid target and are masked out of the loss). This task has a clean, known-in-advance correct solution — attend from position `i` to position `i-2` and copy — so it is a fair target for "which head learned the thing this task needs":

```
step    0  loss 2.2155  val_acc 0.1204
step  100  loss 0.8340  val_acc 0.6304
step  200  loss 0.0808  val_acc 0.9690
step  300  loss 0.0090  val_acc 0.9998
step  400  loss 0.0026  val_acc 1.0000
step  599  loss 0.0007  val_acc 1.0000

baseline (no ablation): loss=0.0007  acc=1.0000
```

Ablate each of the four heads, one at a time, both ways, on a held-out 1024-example batch:

| head | zero-ablation loss (Δ) | zero-ablation acc (Δ) | mean-ablation loss (Δ) | mean-ablation acc (Δ) |
|---|---|---|---|---|
| 0 | 0.0099 (+0.0091) | 0.9977 (−0.0023) | 0.0046 (+0.0038) | 0.9991 (−0.0009) |
| 1 | 2.4106 (+2.4099) | 0.6539 (−0.3461) | 2.2536 (+2.2529) | 0.6396 (−0.3604) |
| 2 | 0.7833 (+0.7826) | 0.8174 (−0.1826) | 0.7757 (+0.7750) | 0.8124 (−0.1876) |
| 3 | 0.0122 (+0.0115) | 0.9967 (−0.0033) | 0.0069 (+0.0062) | 0.9979 (−0.0021) |

Two things in this table, together, are the lesson. First, **the effect is heavily concentrated, but not on a single head alone**: head 1 accounts for the largest share of the damage (loss delta `+2.41`, accuracy collapsing from `1.000` to `0.65`), head 2 carries a real, non-trivial secondary effect (`+0.78`, accuracy to `0.82`), and heads 0 and 3 barely register (`+0.01` each). The task itself needs exactly one attention pattern — but nothing in gradient descent promises the *learned solution* will place all of that function in exactly one head; here it landed mostly, not entirely, in head 1, with head 2 apparently picking up a partial, redundant piece of the same job. This is the "one head learned the shift-2 pattern" story a heatmap would have suggested — recognizably true of head 1, incompletely true of the model as a whole, and Lesson 2 is about exactly this kind of gap between "the dominant head" and "the only head that matters." Second — and this is Lesson 1's actual point — **zero-ablation and mean-ablation agree closely for three of the four heads**, within a few hundredths (heads 0, 2, 3). For the most-affected head they diverge by more — `2.41` vs. `2.25`, roughly 7% of the effect size — real, but still the same qualitative story (large, concentrated damage), not a reversal. That partial agreement is not guaranteed by the method; it is a fact about *this* architecture that had to be measured, and here is why it happened: this block's `LayerNorm(x + Sublayer(x))` renormalizes every token's full feature vector immediately after the attention output is added back in, which partially absorbs a constant shift introduced by *either* ablation method before it ever reaches the FFN or the readout — enough to bring three of the four heads into near-exact agreement, not quite enough to erase the gap on the head doing the most work. A different placement (Pre-LN) or a deeper stack ablated at a later block can show the two methods diverging further — Lab M08-A has you check how much they do, on your own trained model, rather than assume the answer from this table.

**What "out-of-distribution" means here, made precise instead of asserted.** Across 1,024 held-out examples (10,240 token positions), the *minimum* L2 norm of head 1's context vector, ever observed, was `1.1184`; the mean was `3.6822`. The zero vector — what zero-ablation substitutes — has norm exactly `0`, which is not just smaller than typical, it is **outside the entire observed range** for that head, on every one of 10,240 samples. The mean-ablation replacement, by construction, sits at the centroid of that same distribution — a value the head plausibly could have produced. This is the concrete content behind "zero-ablation is a distributional-shift intervention, not just an information-removal intervention": it forces the rest of the network to process an input it was never shown a single time during training, on top of whatever effect removing the head's information has. That the final loss numbers in this table mostly agreed anyway does not make the distinction disappear — it means this particular network's LayerNorm was good, though not perfect, at cleaning up after it.

**Named misconception 1 — "a large attention weight on a token means that token, and the head attending to it, caused the correct answer."** This is the single most common conflation in informal model interpretation, and it is precisely the association-vs-intervention error this lesson opens with. A large attention weight is an *observation*: it says the softmax assigned that token a large coefficient in a weighted sum. It says nothing about whether removing that pathway changes the output at all — a head can attend heavily and redundantly to information that three other heads also carry (Lesson 2's entire subject), in which case ablating it produces almost no effect despite the "high attention" heatmap looking exactly as dramatic as head 1's did above. Jain & Wallace's 2019 finding that attention weights often fail to correlate with gradient-based or ablation-based importance measures, and the subsequent (real, ongoing) debate over when attention *is* informative, both start from this same fact: a weight is not an effect size, and only an intervention measures an effect size.

**Named misconception 2 — "zero-ablation is the standard, 'default' way to ablate, and other methods are exotic variants."** Zero-ablation is common because it is the simplest to implement, not because it is methodologically privileged. The off-distribution argument above is a real cost specific to zero-ablation that mean-ablation (and other variants — resampling a head's context from a *different*, unrelated input, sometimes called noise- or resample-ablation) were specifically designed to reduce. Treating zero-ablation's number as "the" ablation effect, without checking whether a mean-ablation control agrees, is exactly the gap this lesson's worked example was built to make checkable rather than assumed — sometimes, as measured above, it doesn't matter; sometimes it does, and you cannot know which without running both.

**Named misconception 3 — "if I can name a plausible mechanism for how a component might matter, that's evidence it matters."** A plausible mechanism is a *hypothesis*, and this entire module exists because hypotheses about trained networks are cheap to generate and frequently wrong — the task was explicitly designed so that "one head should specialize in the offset-2 lookup" is a reasonable a-priori guess, and the measured table confirms it this time. Lesson 4's multi-seed data shows a version of this same model where the guess is right about *which mechanism* exists but wrong about *which head* implements it, every single time you retrain. A mechanism you can narrate is not a mechanism you have shown; the ablation table is the showing.

### Lesson 2 — The redundancy trap: near-zero ablation effect is not evidence of near-zero function

Lesson 1's task was built to need exactly one attention pattern, and one head learned it, and ablating that head broke the model while ablating the other three barely registered. That is the easy case. **Most learned functions do not have that clean a story, because gradient descent has no preference for parsimony** — if two heads can both learn to carry the same useful signal, and doing so lowers the loss, nothing in the training objective favors one head doing it alone over two heads doing it redundantly. When that happens, ablating either head alone shows almost no effect, because the other one is still there covering for it. **A component that shows a near-zero single-ablation delta has not been shown to do nothing — it has been shown that removing it alone, while everything else stays intact, doesn't hurt.** Those are different claims, and the second one licenses no conclusion about the first.

**Worked example — a task built to reward redundancy, and a pair-ablation result that contradicts what the single-ablation table alone would tell you.** A second one-block, 4-head model, same architecture, trained on a **copy-first** task: `target[i] = input[0]` for every position `i` — every output position needs the same one piece of information, the first token, which is cheap and useful enough for more than one head to learn to fetch it.

```
step    0  loss 2.1997  val_acc 0.1121
step  100  loss 0.0152  val_acc 1.0000
step  499  loss 0.0008  val_acc 1.0000

baseline: loss=0.0008  acc=1.0000
```

Single-head zero-ablation, all four heads:

| head | loss (Δ) | acc (Δ) |
|---|---|---|
| 0 | 0.0014 (+0.0005) | 1.0000 (+0.0000) |
| 1 | 0.0024 (+0.0015) | 1.0000 (+0.0000) |
| 2 | 0.0063 (+0.0055) | 1.0000 (+0.0000) |
| 3 | 0.0351 (+0.0343) | 0.9877 (−0.0123) |

Read on its own, this table says: "head 3 matters a little, heads 0-2 essentially don't." Now ablate every pair of heads together and compare the *measured* joint effect against the **additive prediction** — what you'd expect if each head's contribution were independent and effects just summed:

| pair | actual loss (Δ) | additive prediction (Δ) | synergy (actual − predicted) |
|---|---|---|---|
| (0,1) | 0.0048 (+0.0039) | +0.0021 | +0.0019 |
| (0,2) | 0.0752 (+0.0744) | +0.0060 | +0.0684 |
| (0,3) | 0.0718 (+0.0710) | +0.0348 | +0.0362 |
| (1,2) | 0.2686 (+0.2678) | +0.0070 | **+0.2608** |
| **(1,3)** | **0.6322 (+0.6313)** | **+0.0358** | **+0.5956** |
| (2,3) | 0.0809 (+0.0800) | +0.0397 | +0.0403 |

The pair `(1,3)` is catastrophic — loss jumps to `0.63`, accuracy falls to `87.4%`, nearly eighteen times worse than the additive prediction from the two singles. `(1,2)` shows the same pattern at a smaller scale. And **head 1 — the head whose single-ablation delta (`+0.0015`) was the second-smallest of all four, barely above head 0's `+0.0005`** — is a member of *both* of the two largest-synergy pairs in the table. A study that ran single-head ablation only, saw head 1's `+0.0015`, and reported "head 1 is not important" would have been contradicted by an experiment it never ran. Head 1 was never doing nothing; it was doing something that heads 2 and 3 could each independently substitute for, right up until *both* of its backups were removed at once, or right up until it was removed alongside the one head it happens to be entangled with.

**What this does and doesn't license.** It does not mean "always run every pairwise ablation" — for a `12`-head model that's `66` pairs, and a `96`-head model makes exhaustive pair search impractical, which is exactly why the interpretability literature has developed cheaper targeted alternatives (activation patching / causal tracing, which swaps in an activation from a *different* run at a specific location to localize an effect without a full combinatorial search; you will meet this properly in AIE-204). What it licenses, and what this module holds you to, is narrower and non-negotiable: **a single-ablation table with several near-zero entries is evidence of redundancy risk, not evidence of unimportance, and a defensible ablation study says so explicitly rather than reporting the single-ablation numbers as if they were the whole answer.**

**Named misconception 1 — "if ablating a component alone barely changes the loss, that component isn't doing meaningful work."** Refuted directly and numerically by head 1's own row: second-smallest single-ablation delta in the table, and a member of the two largest synergy pairs. The correct, narrower claim single-ablation supports is: "removing this component alone, while its likely backups stay intact, does not meaningfully hurt" — which is a statement about the *system's redundancy*, not about the component's *function*.

**Named misconception 2 — "ablation effects are additive, so testing components one at a time and summing the deltas approximates testing them together."** The synergy column refutes this directly — `(1,3)`'s actual effect is nearly eighteen times its additive prediction. Additivity would hold if the two heads' contributions were independent causal pathways to the loss; the large positive synergy is exactly what non-independent, mutually-compensating pathways produce, and there is no way to distinguish "independent, small effects" from "redundant, large latent effects" from single-ablation numbers alone — the pair (or a cheaper causal-tracing substitute) has to actually be run.

**Named misconception 3 — "redundancy is a rare edge case in well-trained models, so a single-ablation sweep is usually sufficient."** The copy-first task above is about as simple a task as this course builds — one useful, cheap-to-learn fact needed at every position — and it produced two overlapping redundant pairs out of six possible, in a four-head model. Redundancy is not a pathology confined to unusual architectures; it is close to the *default* outcome whenever a task offers more than one gradient-accessible path to a useful signal, which is most of the time, at essentially every scale this course will touch.

### Lesson 3 — Structural components: post-hoc surgery and retraining-without answer different questions

Lessons 1-2 ablated attention heads — an intervention on `context`, leaving every weight matrix's shape and the surrounding architecture untouched. This lesson ablates something structural: a residual connection, or a normalization layer — and the moment you do that, a new fork in the experiment design opens up that head-ablation never had to confront. You can perform the intervention **post-hoc**, on the exact weights a model already learned with that component present, and see what those specific weights do without it. Or you can perform it **structurally**, retraining an otherwise-identical model that never had the component from the start, and see what weights the network learns *around* its absence. These are not two measurements of the same fact. They are two different experiments, and the field's own ablation tables routinely blur which one was run.

**Post-hoc removal asks: were these specific learned weights relying on this component being present?** The training process shaped every downstream weight under the assumption that this component's contribution would be there, every forward pass, forever. Delete it after the fact and every weight downstream is now processing a distribution it has never seen — not "an input that doesn't need this information," but "an input that is missing a fixed additive term (or a fixed rescaling) the whole rest of the network was calibrated around." **Retraining without it asks: can a network of this architecture learn to solve this task without that component at all?** This is a question about the *function class*, not about one specific set of weights — gradient descent gets to route around the missing piece from step zero, using whatever the remaining components can be shaped into instead.

**Worked example — a residual connection, ablated both ways, on a stack deep enough for the difference to be dramatic.** A six-block encoder, same shift-2 task as Lesson 1, trained with residual connections at every block:

```
full-residual model, trained normally:                       acc = 1.0000
```

**Post-hoc surgery** — take that exact trained model, `deepcopy` it, and flip `use_residual = False` on blocks 3, 4, and 5 (no retraining, identical weights everywhere):

```
post-hoc residual removal on blocks 3,4,5 (same weights):    acc = 0.1159
```

**Structural retrain** — a fresh model, identical architecture and hyperparameters, with blocks 3, 4, and 5 built `use_residual=False` from the very first training step:

```
retrained from scratch with no residual on blocks 3,4,5:     acc = 0.3961
```

Chance-level accuracy on this 8-token vocabulary is `1/8 = 0.1250`. The post-hoc number, `0.1159`, is not merely bad — it is *below chance*, meaning the surgically altered network is doing worse than a model that ignored the input and guessed uniformly at random: the missing identity path so badly corrupts the activation statistics blocks 4-5's weights were calibrated for that their output actively points away from the right answer, not just toward no answer. The retrained number, `0.3961`, is a real, substantial degradation from the full model's `1.0000` — three residual-free blocks genuinely cost this network most of its accuracy — but it is more than three times chance, meaning the network **found a working, if considerably worse, solution** once it never had the residual path to lean on and had to route information around its absence from the start. Both numbers are real measurements of "removing the residual connection from blocks 3-5." They differ by a factor of roughly 3.4×, in opposite directions relative to chance, because they are answers to two different questions.

**A second structural ablation, run the identical two ways, with the opposite result — reported honestly, not tuned to make a point.** Post-hoc-disabling `LayerNorm` (replacing it with the identity function) on the same three blocks of the same trained model produced **no** measurable accuracy loss (`1.0000 → 1.0000`), and neither did retraining without it (`1.0000`). Task accuracy alone says LayerNorm was inert here. But tracing the mean hidden-state norm through the stack tells a different, quieter story: with LayerNorm intact, the norm at the final block averaged `7.58`; with it removed from blocks 3-5, the same measurement reached `10.94` — a real ~44% growth in activation scale that the accuracy metric never surfaced, because this particular readout layer happened to tolerate the shift. **This is not a contradiction of the residual result — it is the same lesson from the other direction: whether a structural component turns out to be load-bearing, and by which measurement, is an empirical fact about *this* trained system, never a property you get to import from "residual connections are important" or "normalization prevents instability" as general folklore.** Both of those statements are usually true. Neither is a substitute for measuring the specific model in front of you.

**Named misconception 1 — "if removing a component post-hoc craters performance, the component was doing exactly the function I hypothesized."** The `0.1159` number — below chance, on a task with a single unambiguous correct behavior — is consistent with several different explanations: the residual path specifically carried the shift-2 information forward (the "clean" story), *or* the sudden distributional shift alone was enough to push blocks 4-5 into a region of their input space where their learned weights compute something close to noise, regardless of what specific information was lost. Post-hoc collapse is strong evidence that the component's presence matters to *this trained instance* — it is not, by itself, evidence for *which* function the component was performing. Distinguishing those requires more than one ablation (Lesson 4).

**Named misconception 2 — "post-hoc ablation and retrain-without ablation are two ways of measuring the same underlying fact, so either one is fine to run, or averaging them is reasonable."** The residual worked example refutes this at the level of raw numbers, not just interpretation: `0.1159` and `0.3961` are not two noisy estimates of one true value — they are correct answers to two different, both-legitimate questions ("does this trained network need it," "can this architecture learn without it"), and a report that collapses them into one number, or worse, cites whichever one supports its thesis, has made an error a skeptical reader is entitled to catch.

**Named misconception 3 — "a structural ablation that shows no accuracy effect proves the component is unnecessary and can be safely dropped from the design."** The LayerNorm result's own second measurement — the ~44% hidden-state norm growth that the accuracy metric missed entirely — refutes the inference from "the metric I checked didn't move" to "nothing changed." A defensible structural ablation study checks more than the single headline metric the task happens to be graded on, precisely because a tolerant downstream layer can absorb a real internal shift and hide it from exactly the number you were watching.

### Lesson 4 — Attribution as an experiment design: controls, seeds, and the write-up a skeptical reader would trust

Lessons 1-3 each produced one clean, dramatic table. That is a curriculum-writing artifact, not a promise about your own experiments: every one of those tables is the *result* of a design decision — which ablation method, which components, how many seeds, what counts as a control — and a different set of decisions on the identical model and task can produce a materially different, equally "clean-looking" table that supports a wrong conclusion. This lesson is about the decisions themselves, because the certification artifact for this module is not a table — it's a written ablation study, and the rubric (see Assessment) grades whether that write-up would survive a reader who already knows everything Lessons 1-3 taught.

**A single trained model is one sample from a distribution over trained models, and ablation results do not automatically generalize across that distribution.** Retrain Lesson 1's shift-2 model five times, changing only the random seed, and ablate all four heads in every one of the five:

| seed | head 0 Δloss | head 1 Δloss | head 2 Δloss | head 3 Δloss | top head | top Δloss |
|---|---|---|---|---|---|---|
| 0 | 0.0091 | **2.4099** | 0.7826 | 0.0115 | 1 | 2.4099 |
| 1 | 0.0007 | 0.0032 | 0.0032 | **2.1015** | 3 | 2.1015 |
| 2 | 0.0003 | 0.0005 | **4.9517** | 0.0013 | 2 | 4.9517 |
| 3 | 0.0001 | **1.8326** | 0.1821 | 0.0003 | 1 | 1.8326 |
| 4 | 0.0031 | 0.0020 | 0.0008 | **0.5530** | 3 | 0.5530 |

Two facts, both load-bearing. First: **the "shift-2 head" is a different head index every time** — 1, 3, 2, 1, 3 across five seeds — because which of the four symmetric, randomly-initialized heads ends up specializing in the task's one needed function is itself a random outcome of training, not a fact about the architecture. "Head 1 learned the offset-2 lookup" (Lesson 1's claim, true of that one specific run) is not the same claim as "this architecture routes offset-2 information through its second head" — the second claim is false, and a report that phrases the first claim the way the second one sounds has overclaimed. Second: **the magnitude of the top head's own effect varies by nearly an order of magnitude** — from `0.55` to `4.95`, mean `2.37`, standard deviation `1.44`, on the *identical* task, architecture, and training procedure, differing only in the random seed. A report built from one seed's `2.41` and presented as *the* effect size of "the shift-2 head" is reporting a single draw from a distribution with a standard deviation more than half its own mean, without saying so.

**A control condition is not optional — it is what turns "ablating my hypothesized component hurt" into evidence that the hypothesized component, specifically, is why.** Look back at Lesson 1's own table: head 1's effect (`+2.41`) is large — but large *compared to what*? The other three heads in that same table, ablated the same way, on the same model, are the control: mean of heads 0, 2, 3's deltas is `≈0.27`, so head 1's effect is roughly nine times the average of a matched, comparable intervention on components *not* hypothesized to matter. That comparison — not the raw `+2.41` in isolation — is what licenses "head 1 is unusually important," because it rules out the alternative explanation "ablating literally any head in this model costs about this much." A report that states one component's ablation delta with no comparison point has shown that *an* intervention had *an* effect, and nothing about whether that effect is distinctive.

**A falsification condition, stated before running, is what separates a prediction from a post-hoc story.** "I predict head 1 will show the largest effect, because Lesson 1's task requires exactly one attention pattern and I expect one head to specialize" is a prediction that Lesson 4's own five-seed table would have *refuted* on seeds 1, 2, and 4 — a real, useful, falsifiable claim, wrong two-thirds of the time about *which* head, right every time about *the shape of the effect* (concentrated in one head, not spread evenly across four). Writing the prediction down first, and reporting when it was wrong and what you learned from being wrong, is not a formality this module imposes for its own sake — it is the only mechanism that stops an ablation study from becoming a search for whichever post-hoc narrative fits whatever number came out.

**Named misconception 1 — "the ablation delta is the whole finding; report the number and move on."** Every worked example in this module needed at least a second measurement — a control (Lesson 1: mean-ablation as a check on zero-ablation; Lesson 4: the other three heads as a check on head 1), a second condition (Lesson 3: post-hoc vs. retrained), or a second metric (Lesson 3: hidden-state norm alongside accuracy) — before the single headline delta meant what it appeared to mean on its own. A number without its comparison point is not yet a finding.

**Named misconception 2 — "gradient-based attribution (e.g. integrated gradients, saliency) and ablation-based attribution are competing methods, and you should pick the more rigorous one."** They answer related but distinct questions and are properly complementary, not competitive: a gradient-based method estimates, locally, how much a *small* change in a component's activation would change the output — cheap to compute, differentiable, but a local linear approximation that can miss effects requiring a *large* change (exactly the kind Lesson 2's pair-ablations found, since a small perturbation to head 1 alone, with head 3 still fully present, may show a small gradient precisely because head 3 is compensating in that local neighborhood too). Ablation measures the actual, non-local, "component fully absent" effect directly, at the cost of being combinatorially expensive to run exhaustively. A defensible study states which question each method it used actually answers, rather than treating either as a strictly superior stand-in for the other.

**Named misconception 3 — "a compute/capacity confound means ablated-head comparisons are unfair unless the model is retrained smaller to match parameter count."** Worth naming precisely because it's *almost* right and the exact place it goes wrong matters: for the context-level ablation this module performs (Lessons 1-2), `Wq`/`Wk`/`Wv`/`Wo` keep their exact shape and every parameter stays in the model — nothing shrinks, so there is no parameter-count confound to correct for. The real confound at this level is the one Lesson 4's control section addresses directly: is the measured effect distinctive to *this* component, or would *any* comparably-sized intervention (ablating a random, non-hypothesized head) produce a similar-looking number? That is answered by a matched control condition, not by retraining a smaller model. A genuine parameter-count confound *does* appear the moment you move to Lesson 3's structural, architecture-changing ablations — which is exactly why that lesson insists post-hoc and retrained-from-scratch are different experiments, and why AIE-204 goes further into properly capacity-matched baselines for the cases where parameters really are being removed.

# lab_a_solution.py
import numpy as np
import torch
import torch.nn as nn
import sys
sys.path.insert(0, ".")
from ablation import TinyEncoder

VOCAB, SEQ_LEN, D_MODEL, NUM_HEADS, D_FF = 8, 10, 32, 4, 64
PAD_TARGET = -100


def make_batch(batch_size, rng):
    x = rng.integers(0, VOCAB, size=(batch_size, SEQ_LEN))
    y = np.full((batch_size, SEQ_LEN), PAD_TARGET)
    y[:, 2:] = x[:, :-2]
    return torch.tensor(x, dtype=torch.long), torch.tensor(y, dtype=torch.long)


def accuracy(logits, y):
    mask = y != PAD_TARGET
    correct = (logits.argmax(-1) == y) & mask
    return correct.sum().item() / mask.sum().item()


def train(seed):
    torch.manual_seed(seed)
    rng = np.random.default_rng(seed)
    model = TinyEncoder(VOCAB, D_MODEL, NUM_HEADS, D_FF, SEQ_LEN, num_blocks=1)
    opt = torch.optim.Adam(model.parameters(), lr=3e-3)
    for step in range(600):
        x, y = make_batch(64, rng)
        logits, _, _ = model(x)
        loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), y.reshape(-1), ignore_index=PAD_TARGET)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model, rng


def head_mean_activations(model, x):
    with torch.no_grad():
        _, _, context = model(x)          # (B, h, T, d_k)
    return context.mean(dim=(0, 2))        # (h, d_k)


def ablate_and_measure(model, x, y, num_heads, replacement=None):
    results = {}
    with torch.no_grad():
        for h in range(num_heads):
            logits, _, _ = model(x, ablate_heads=[h], replacement=replacement)
            loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), y.reshape(-1), ignore_index=PAD_TARGET).item()
            acc = accuracy(logits, y)
            results[h] = (loss, acc)
    return results


if __name__ == "__main__":
    model, rng = train(seed=0)
    xv, yv = make_batch(1024, rng)

    with torch.no_grad():
        logits, _, _ = model(xv)
        base_loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), yv.reshape(-1), ignore_index=PAD_TARGET).item()
        base_acc = accuracy(logits, yv)
    print(f"baseline: loss={base_loss:.4f} acc={base_acc:.4f}")

    mean_per_head = head_mean_activations(model, xv)

    zero_results = ablate_and_measure(model, xv, yv, NUM_HEADS, replacement=None)
    mean_results = ablate_and_measure(model, xv, yv, NUM_HEADS, replacement=mean_per_head)

    print("\nhead | zero-ablation Δloss | mean-ablation Δloss")
    for h in range(NUM_HEADS):
        zl, _ = zero_results[h]
        ml, _ = mean_results[h]
        print(f"  {h}  |  {zl - base_loss:+.4f}            |  {ml - base_loss:+.4f}")

    # off-distribution check on the single most-affected head
    top_head = max(zero_results, key=lambda h: zero_results[h][0])
    with torch.no_grad():
        _, _, context = model(xv)
    vecs = context[:, top_head, :, :].reshape(-1, context.shape[-1])
    norms = vecs.norm(dim=-1)
    print(f"\nhead {top_head} context-vector norm: min={norms.min():.4f} mean={norms.mean():.4f} max={norms.max():.4f}")
    print(f"zero vector's norm (0.0) is {'OUTSIDE' if norms.min() > 0 else 'inside'} the observed range")

# lab_b_solution.py
import numpy as np
import torch
import torch.nn as nn
from itertools import combinations
import sys
sys.path.insert(0, ".")
from ablation import TinyEncoder

VOCAB, SEQ_LEN, D_MODEL, NUM_HEADS, D_FF = 8, 10, 32, 4, 64


def make_batch(batch_size, rng):
    x = rng.integers(0, VOCAB, size=(batch_size, SEQ_LEN))
    y = np.repeat(x[:, [0]], SEQ_LEN, axis=1)
    return torch.tensor(x, dtype=torch.long), torch.tensor(y, dtype=torch.long)


def accuracy(logits, y):
    return (logits.argmax(-1) == y).float().mean().item()


def train(seed):
    torch.manual_seed(seed)
    rng = np.random.default_rng(seed)
    model = TinyEncoder(VOCAB, D_MODEL, NUM_HEADS, D_FF, SEQ_LEN, num_blocks=1)
    opt = torch.optim.Adam(model.parameters(), lr=3e-3)
    for step in range(500):
        x, y = make_batch(64, rng)
        logits, _, _ = model(x)
        loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), y.reshape(-1))
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model, rng


def single_ablation_deltas(model, x, y, base_loss, num_heads):
    deltas = {}
    with torch.no_grad():
        for h in range(num_heads):
            logits, _, _ = model(x, ablate_heads=[h])
            loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), y.reshape(-1)).item()
            deltas[h] = loss - base_loss
    return deltas


def pairwise_ablation_table(model, x, y, base_loss, single_deltas, num_heads):
    table = {}
    with torch.no_grad():
        for h1, h2 in combinations(range(num_heads), 2):
            logits, _, _ = model(x, ablate_heads=[h1, h2])
            loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), y.reshape(-1)).item()
            actual = loss - base_loss
            additive = single_deltas[h1] + single_deltas[h2]
            table[(h1, h2)] = (actual, additive, actual - additive)
    return table


if __name__ == "__main__":
    model, rng = train(seed=0)
    xv, yv = make_batch(1024, rng)
    with torch.no_grad():
        logits, _, _ = model(xv)
        base_loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), yv.reshape(-1)).item()
        base_acc = accuracy(logits, yv)
    print(f"baseline: loss={base_loss:.4f} acc={base_acc:.4f}")

    singles = single_ablation_deltas(model, xv, yv, base_loss, NUM_HEADS)
    print("\nsingle-ablation Δloss:", {h: round(d, 4) for h, d in singles.items()})

    pairs = pairwise_ablation_table(model, xv, yv, base_loss, singles, NUM_HEADS)
    print("\npair | actual Δloss | additive prediction | synergy")
    for (h1, h2), (actual, additive, synergy) in sorted(pairs.items(), key=lambda kv: -kv[1][2]):
        print(f"  ({h1},{h2}) | {actual:+.4f}       | {additive:+.4f}              | {synergy:+.4f}")

    worst_pair = max(pairs, key=lambda k: pairs[k][2])
    print(f"\nlargest synergy: pair {worst_pair}, "
          f"whose singles were {singles[worst_pair[0]]:+.4f} and {singles[worst_pair[1]]:+.4f}")

# lab_c_solution.py
import numpy as np
import torch
import torch.nn as nn
import copy
import sys
sys.path.insert(0, ".")
from ablation import TinyEncoder

VOCAB, SEQ_LEN, D_MODEL, NUM_HEADS, D_FF = 8, 10, 32, 4, 64
NUM_BLOCKS = 6
OFF_BLOCKS = [3, 4, 5]
PAD_TARGET = -100
CHANCE = 1.0 / VOCAB


def make_batch(batch_size, rng):
    x = rng.integers(0, VOCAB, size=(batch_size, SEQ_LEN))
    y = np.full((batch_size, SEQ_LEN), PAD_TARGET)
    y[:, 2:] = x[:, :-2]
    return torch.tensor(x, dtype=torch.long), torch.tensor(y, dtype=torch.long)


def accuracy(logits, y):
    mask = y != PAD_TARGET
    correct = (logits.argmax(-1) == y) & mask
    return correct.sum().item() / mask.sum().item()


def train(off_blocks, seed, steps=1200):
    torch.manual_seed(seed)
    rng = np.random.default_rng(seed)
    model = TinyEncoder(VOCAB, D_MODEL, NUM_HEADS, D_FF, SEQ_LEN, num_blocks=NUM_BLOCKS)
    for b in off_blocks:
        model.blocks[b].use_residual = False
    opt = torch.optim.Adam(model.parameters(), lr=3e-3)
    for step in range(steps):
        x, y = make_batch(64, rng)
        logits, _, _ = model(x)
        loss = nn.functional.cross_entropy(logits.reshape(-1, VOCAB), y.reshape(-1), ignore_index=PAD_TARGET)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model, rng


def post_hoc_surgery(model, off_blocks):
    surgery = copy.deepcopy(model)
    for b in off_blocks:
        surgery.blocks[b].use_residual = False
    return surgery


if __name__ == "__main__":
    print("training baseline (residual everywhere)...")
    baseline_model, rng = train(off_blocks=[], seed=0)
    xv, yv = make_batch(2048, rng)
    with torch.no_grad():
        logits, _, _ = baseline_model(xv)
        base_acc = accuracy(logits, yv)
    print(f"baseline acc: {base_acc:.4f}")

    surgery_model = post_hoc_surgery(baseline_model, OFF_BLOCKS)
    with torch.no_grad():
        logits, _, _ = surgery_model(xv)
        surgery_acc = accuracy(logits, yv)
    print(f"post-hoc residual removal on blocks {OFF_BLOCKS} (same weights): acc={surgery_acc:.4f}")

    print(f"\ntraining from scratch with residual OFF on blocks {OFF_BLOCKS}...")
    retrained_model, rng2 = train(off_blocks=OFF_BLOCKS, seed=0)

    print(f"retrained-without-residual acc: {retrained_acc:.4f}")

    print(f"\nchance level: {CHANCE:.4f}")
    print(f"summary: baseline={base_acc:.4f}  post-hoc={surgery_acc:.4f}  retrained={retrained_acc:.4f}")

## Assessment

**Component:** ablation project (25% of AIE-202's overall grade, per the course syllabus). **Format:** a written ablation study, produced against an unseen setup, graded on the judgment trail — predict, control, attribute, prove — never on "the report sounds authoritative."

**The setup.** You receive (generated by the instructor from a variant of this module's own `ablation.py` harness, with the random seed withheld) a trained checkpoint of a `TinyEncoder`, its architecture hyperparameters, and a short description of the task it was trained on — but **not** which component, if any, was engineered to matter, and **not** whether any component pair is redundant. Somewhere in that model is at least one planted trap drawn directly from this module's own lessons: a component whose single-ablation effect is small because a partner component compensates for it (Lesson 2), and/or a structural component (a residual connection or a normalization layer) whose post-hoc removal and retrained-from-scratch removal would tell substantially different stories (Lesson 3) if you ran both.

**The deliverable.** A written ablation study — code plus a report — that a reader who has completed this module (i.e., already knows about redundancy, distributional shift, and post-hoc-vs-retrained) would find convincing. At minimum, it must contain:

1. **A written prediction, filed before your first ablation run,** stating which component(s) you hypothesize matter, by what mechanism, and what result would prove that hypothesis wrong.
2. **At least two ablation methods on the same component(s)** (zero- and mean-ablation at minimum) with both results reported, not just the more dramatic one.
3. **A combinatorial or targeted follow-up** triggered specifically by any single-ablation result that came back small — either a pairwise sweep or a stated, justified reason none was needed.
4. **A control condition** — a comparably-sized ablation on a component *not* hypothesized to matter, reported alongside the hypothesized component's result, so the reader can judge whether the effect is distinctive.
5. **Multiple seeds or an equivalent resampling scheme**, with a reported spread (not a single point estimate), for any claim about effect *magnitude* — and an explicit statement of what varies and doesn't vary across seeds for your specific finding.
6. **An explicit statement of scope** for any structural claim: "this is true of this trained instance" vs. "this is true of the architecture," with the post-hoc/retrained distinction named if a structural component was touched.
7. **A stated falsification condition and an honest account of whether it fired** — what result, if you'd seen it, would have meant your hypothesis was wrong, and did you see anything like it.

A report satisfying 1-7 but reaching an incorrect conclusion about which component matters scores higher on this rubric than a report reaching the correct conclusion via a single zero-ablation run on one seed with no control — the artifact being graded is the experiment design, not whether the headline number happens to match the instructor's oracle run.

**Gaming-resistant rubric.**

| Criterion | Fails to demonstrate | Meets bar | Exceeds bar |
|---|---|---|---|
| **Predict** | No prediction filed before running, or an unfalsifiable one ("something in attention matters") | States a specific component, a mechanism, and a falsification condition, before any ablation is run | Prediction also states which *other* result (e.g. a specific pair, a specific seed spread) would distinguish "clean single effect" from "hidden redundancy" before that distinction is tested |
| **Method breadth** | Zero-ablation only, single component, single run | Zero- and mean-ablation reported for every hypothesized component; both numbers shown even when they agree | Also runs a third method (e.g. resample-ablation) or an activation-level check (e.g. the off-distribution norm argument from Lesson 1) when zero/mean disagree |
| **Redundancy check** | Reports single-ablation deltas only; near-zero deltas treated as "unimportant" with no follow-up | Runs a pairwise (or clearly justified targeted) follow-up on any near-zero single result before concluding it doesn't matter | Follow-up is chosen by a stated reason (e.g. shared functional role hypothesized from the task, not "checked all pairs because I had time") |
| **Controls** | No non-hypothesized component tested for comparison; the hypothesized component's number is reported in isolation | At least one matched control ablation reported alongside the finding, with an explicit comparison ("N times the control's effect") | Control is chosen to rule out a *specific*, named alternative explanation for the effect, not just "some other head" |
| **Structural scope** | A structural (residual/normalization) claim stated without saying whether it was tested post-hoc, retrained, or both | Both post-hoc and retrained-from-scratch results reported for any structural claim, with the two numbers not conflated | Explicitly predicts, before running, whether the two would land in the same or different outcome bands, and reconciles the actual result against that prediction |
| **Uncertainty** | A single seed's number reported as *the* effect size, no spread | ≥3 seeds (or an equivalent resampling scheme) reported for the headline magnitude claim, with a spread (range or std), not a bare mean | Spread is used to state, explicitly, which part of the finding is seed-stable (e.g. "effect concentrates in one head") and which is seed-unstable (e.g. "which specific head") |
| **Honesty about the falsification condition** | The write-up never states what would have counted as evidence against the hypothesis, or claims the prediction was confirmed without checking against the stated condition | Explicitly revisits the pre-registered falsification condition and states whether it fired | A wrong initial prediction is reported as such, with the revised understanding — not silently corrected as if it had been the prediction all along |

A learner who runs one zero-ablation sweep, finds one large number, and writes a fluent paragraph about what that component "must be doing" fails **Method breadth**, **Redundancy check**, and **Uncertainty** even if the component they named happens to be the one the instructor's checkpoint was built around — the rubric is designed so a correct-sounding conclusion reached by an indefensible process scores below an honestly-reported inconclusive one.

## Three-tier reading — ablation and attribution

**Tier 1 — material ground, checkable.** Ablation-based attribution is standard, load-bearing methodology across the interpretability literature — from early lesion-style studies in neuroscience it borrows its logic from, through the transformer circuits and causal-tracing work this module's pairwise and post-hoc-vs-retrained distinctions echo. It is also, documented by the field's own methodology critiques (not this course's opinion), routinely under-controlled in published work: single-seed reports, single-ablation-method reports, and post-hoc/retrained conflations of exactly the kind this module's labs are built to catch all appear regularly in peer-reviewed ablation tables, not just informal blog-post interpretability claims.

**Tier 2 — what the field doesn't say out loud.** An ablation table with one clean number and no control condition, no seed variance, and no stated falsification condition is not automatically dishonest — it is frequently just what got past review, because "we ablated X and performance dropped by Y%" reads as rigorous *empirical* work in a field where a lot of competing claims are purely architectural or purely theoretical, and a number with an error bar looks, to a skimming reader, barely different from a number without one. The gap this module keeps closing — is the effect distinctive from a matched control, does it survive a second seed, does it survive a second ablation method, is "necessary" a claim about this trained instance or the whole architecture — is exactly the gap that "we ran an ablation study" tends to paper over in both directions: boosters cite a favorable ablation table as proof a component is essential without checking whether *any* comparable ablation would have looked similarly bad; critics cite an unfavorable one as proof a component is vestigial without checking whether redundancy, not irrelevance, explains a small single-ablation delta. The tooling to check either claim is exactly what this module built. Most published ablation tables were not built with it, and most readers of those tables have no way to tell which ones were.

**Tier 3 — sit with this, don't resolve it.** You can now design an ablation study a genuinely skeptical reader — one who knows about redundancy, distributional shift, and the post-hoc/retrained distinction — would trust. Most of the ablation claims that justify real decisions about real deployed models were not built to that standard, and you now have enough of this module's own numbers to know exactly how much that can matter: a single-seed report would have named a different head as "the important one" in three of your five training runs, and a single-ablation report would have called head 1 harmless when it was a load-bearing partner in the model's two worst failure modes. When someone tells you "we ablated the component responsible for this behavior and removed it, so the behavior is fixed," you now know the specific list of questions that determine whether that sentence is evidence or narrative: Which ablation method? How many seeds? Was a redundant partner checked? Was this the trained model, or a retrained one? Most of the time, when that sentence is said about a system whose behavior actually matters, you will not get to ask. Sit with what your confidence in that sentence should be anyway — and with whether "we understand which part does this" was ever a claim about the architecture, or always, secretly, a claim about how much anyone had checked.
