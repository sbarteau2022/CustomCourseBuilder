## Lessons

### Lesson 1 — The recurrence, unrolled: an RNN is a for-loop with shared weights

A sequence — a sentence, a time series, a sensor trace — is a list of vectors `x_0, x_1, ..., x_{T-1}` where **order carries information** the M01/M02 machinery has no way to represent: an `MLP` from M02 takes one fixed-size input and produces one output, with no concept of "the input before this one." The **recurrent neural network (RNN)** fixes this with the smallest possible change to a `Neuron`-shaped computation: keep a running **hidden state** `h_t`, and update it at every timestep using both the new input and the *previous* hidden state:

```
h_t = tanh(Wxh @ x_t + Whh @ h_prev + bh)
```

`Wxh` maps the current input into the hidden space; `Whh` maps the *previous* hidden state into an update to the new one; `bh` is a shared bias. `h_{-1}` (the state before the sequence starts) is conventionally the zero vector. Read the equation again with M01's vocabulary: this is exactly a `Neuron`'s `tanh(sum(w*x) + b)`, except the "inputs" are the concatenation of `x_t` and `h_{t-1}`, and the neuron gets *called again* on its own most recent output. An RNN is not a new kind of mathematics — it is the M01 `Value` graph, called in a `for` loop, where the loop variable is time instead of layer depth.

**The detail that makes it recurrent, not just repeated.** `Wxh`, `Whh`, and `bh` are the *same three `Value` objects*, reused at every timestep — not one fresh weight matrix per position. This is deliberate and load-bearing for two reasons. First, it is what lets the network handle a sequence of *any* length with a fixed number of parameters — a 50-word sentence and a 5-word sentence use the identical `Wxh`/`Whh`/`bh`. Second — and this is where M01 Lesson 3 stops being a footnote and becomes the central mechanism of this entire module — reusing the same `Value` object across `T` timesteps means `Whh`'s `.grad` will receive **`T` separate contributions accumulated via `+=`** during a single `.backward()` call, one per timestep, exactly like the "diamond" `b = a * a` example from M01. `Backpropagation through time` (BPTT) is not a different algorithm from the `.backward()` you already trust — it is the *same* topological-order backward pass, applied to a graph that happens to have this specific, repeated, weight-shared shape.

**Worked example — a 2-hidden-unit RNN, unrolled over 3 timesteps, traced by hand.** `RNNCell(input_size=1, hidden_size=2, seed=11)` draws:

```
Wxh = [[-1.224], [0.378]]
Whh = [[0.704, -0.363],
       [-0.940, -0.046]]
bh  = [0.0, 0.0]
```

Feed the scalar sequence `xs = [0.5, -1.0, 0.8]`, starting from `h = [0.0, 0.0]`:

| t | x_t | z_t = Wxh·x_t + Whh·h_{t-1} + bh | h_t = tanh(z_t) |
|---|---|---|---|
| 0 | +0.50 | `[-0.612, 0.1888]` | `[-0.5456, 0.1866]` |
| 1 | -1.00 | `[0.7725, 0.1264]` | `[0.6484, 0.1258]` |
| 2 | +0.80 | `[-0.5687, -0.3131]` | `[-0.5144, -0.3032]` |

A `Readout` (`Why = [-0.664, -1.225]`, `by = 0.0`) turns the final hidden state into a scalar prediction: `yhat = Why · h_2 = 0.7129`. Against a target of `1.0`, `loss = (yhat - target)² = 0.0824`. Call `.backward()` on that loss — the same call you've used since M01 — and read off the gradient that flowed all the way back to each timestep's *input*:

```
dL/dx0 = 0.070066
dL/dx1 = 0.237282
dL/dx2 = -0.101746
```

At `T=3`, nothing looks broken: `x0`'s gradient (`0.070`) is smaller than `x2`'s (`-0.102`) but the same order of magnitude — the ratio is `0.69`, not `0.0000...1`. Hold this table in mind; Lesson 2 reruns the identical mechanism at `T=80` and the ratio stops being close to 1 by many, many orders of magnitude. Nothing about the *code* changes between the two — only how many times the loop runs.

**Named misconception 1 — "an RNN learns a different weight for each position in the sequence, the way a `Layer` in an `MLP` has different neurons at different depths."** Refuted directly by the code: `RNNCell.step` is called once per timestep, but it always closes over the *same* `self.Wxh`, `self.Whh`, `self.bh`. There is exactly one set of recurrent weights, full stop, regardless of whether the sequence has 3 tokens or 300. This is the feature that makes RNNs applicable to variable-length input at all — and it is also, as Lesson 2 shows, the exact feature responsible for the vanishing-gradient failure, because "the same weight, applied over and over" is precisely the setup that lets a small contraction factor compound.

**Named misconception 2 — "BPTT is a separate, more complicated algorithm you have to learn on top of ordinary backprop."** It is common to see BPTT introduced with its own derivation, its own name, and its own diagram, which makes it *feel* like new machinery. It is not: `RNNCell.step` builds an ordinary `Value` graph (multiplications, additions, a `tanh`), the same primitives from M01, called repeatedly. `.backward()` — the exact function from M01 Lesson 3, unmodified — builds the topological order over however many nodes that graph turned out to have (which grows with `T`) and walks it in reverse. "BPTT" is the name people give to *what that ordinary process looks like* when the graph has this specific, time-unrolled, weight-shared shape — not a different process.

### Lesson 2 — The vanishing gradient, measured live

Lesson 1's 3-step example looked fine. This lesson runs the identical mechanism at real length and watches it die — not as a claim to accept, but as a number you will reproduce yourself in Lab M04-A.

**Why it has to happen: a product of Jacobians.** The gradient of the loss with respect to a hidden state `k` steps in the past has to pass through every intervening timestep's local Jacobian. For a `tanh` RNN cell, the local Jacobian at step `t` is (up to a diagonal `tanh'` term) `Whh^T · diag(1 - h_t²)`. The gradient reaching `T` steps back is, informally, a **product of `T` such Jacobians** — and a product of `T` matrices, each with operator norm bounded above by `≤ max(|Whh entries|) * sqrt(hidden_size)` and *also* damped by `(1 - h_t²) ≤ 1` at every single step (since `tanh'` is at most `1`, and less wherever the unit is even partially saturated), shrinks geometrically in `T` whenever that per-step contraction factor is below `1` — which, because of the `tanh'` term alone, it very often is. This is the exact same "geometric compounding" mechanism as M02 Lesson 1's `r = 0.5 * fan_in * std²` recursion — except M02's recursion compounded over **layers** (depth) and this one compounds over **timesteps** (sequence length). Same failure, different axis.

**Worked example — `hidden_size=8`, Xavier-scaled `Whh` (`std = 1/√8 ≈ 0.354`), measuring `|dL/dx_0|` as the sequence gets longer:**

| T | `\|dL/dx_0\|` | loss |
|---|---|---|
| 2 | `3.16e-02` | 0.0052 |
| 5 | `9.86e-04` | 0.0018 |
| 10 | `7.20e-04` | 0.5361 |
| 20 | `3.02e-08` | 0.7500 |
| 30 | `3.52e-12` | 0.0278 |
| 40 | `1.69e-15` | 0.0017 |
| 60 | `2.61e-20` | 1.4065 |
| 80 | `3.92e-29` | 0.3414 |

By `T=80`, the gradient reaching the first input has collapsed by **27 orders of magnitude** relative to `T=2`. Averaged over 5 seeds (to make sure this isn't one unlucky random draw — the same discipline M01/M02 used throughout), the short-sequence (`T=5`) mean gradient is `0.132`; the long-sequence (`T=60`) mean is `4.46e-08` — a ratio of **`~2.97 million`**. That number, not a single run's noisy trajectory, is what Lab M04-A's tests hold you to.

**The forward pass gives you no warning.** Every `h_t` in the table above is a `tanh` output — bounded in `[-1, 1]` by construction, at *every single timestep*, no matter how long the sequence runs. If you only inspected activations (the M02 Lesson 1 diagnostic), a long RNN looks completely healthy the entire time — nothing explodes, nothing collapses to zero, the numbers stay in a comfortable range forever. The gradient is where the damage is, and the gradient is invisible unless you compute it directly. This is a *more* insidious version of M02's "the naive-`tanh` activation std looked almost stable at `~0.9`" trap: there, at least the saturation-fraction column gave a second signal to catch it. Here, the forward pass genuinely has no analogous tell — you have to go looking for the gradient specifically.

**Making `Whh` bigger doesn't save you either.** At `hh_std = 1.5` (deliberately large — the "exploding" regime M02 Lesson 1 would predict for a feedforward net), the sequence gradient does *not* cleanly explode the way a deep MLP's activations did in M02. It bounces — `9.87e-02` at `T=2`, `1.54e-01` at `T=5`, but `1.85e-04` by `T=25` and `1.46e-04` by `T=30` — a genuine, if noisier, collapse over roughly the same range. The mechanism is different from M02's small-weight case but the outcome rhymes: large `Whh` values push `z_t` to extremes, which pushes `h_t = tanh(z_t)` toward saturation (`|h_t| → 1`), which drives `tanh'(z_t) = 1 - h_t² → 0` — the *local* Jacobian gets small again, just via saturation instead of via `Whh` being literally small. There is no "just turn the recurrent weights up" escape hatch inside the RNN architecture itself; both directions of the same dial eventually kill the gradient, one way or another, given enough steps.

**Named misconception 1 — "if the hidden-state values look bounded and reasonable, the gradients must be fine too."** Directly refuted by this lesson's own table: every `h_t` throughout the `T=80` run sits safely inside `[-1, 1]`, and the network's forward output is a normal, plausible number — nothing about *running the model forward* reveals that `dL/dx_0` has collapsed to `3.92e-29`. A learner who only ever inspects forward activations (exactly the habit M02 Lesson 1 built) will conclude a badly-vanishing RNN is healthy. Checking gradients directly, not inferring them from activations, is the discipline this lesson exists to install.

**Named misconception 2 — "vanishing gradients are a small-weight problem, so I can avoid them by initializing `Whh` larger."** Refuted by the `hh_std=1.5` data directly above: the gradient still collapses by several orders of magnitude over the same range of `T`, just via saturation rather than contraction. There are two structurally different roads to the same destination inside a `tanh` RNN, and neither is fixed by moving a single scalar. (This is exactly the setup Lesson 3 needs: the fix that works is not "a better `Whh`," it is a different computational graph.)

### Lesson 3 — Attention: replacing a chain with a lookup

Lesson 2's mechanism is specific: the gradient reaching a distant timestep has to survive a **product of `T` Jacobians**, because the *only path* from `x_0` to the loss is the sequential chain `h_0 → h_1 → ... → h_{T-1} → loss`. Every one of those `T` hops is another multiplication that can shrink the signal. The fix this lesson builds does not try to make each hop survive better (that was Lesson 2's dead end) — it removes the hops. **Attention** connects every input position to the output with **exactly one operation**, regardless of how far apart they are.

**The mechanism, minimal.** Project every token `x_t` into three vectors using three learned linear maps — a **query**, a **key**, and a **value**:

```
q_t = Wq @ x_t      k_t = Wk @ x_t      v_t = Wv @ x_t
```

`Wq`, `Wk`, `Wv` are the same *kind* of object — a linear projection, exactly like `Wxh` in Lesson 1 — differing only in their learned numbers, not their architecture. (This is worth stating plainly because "query," "key," and "value" sound like three different subsystems; they are three copies of the same operation, wearing different names because of the different *role* each result plays next.) To produce one output — here, from a single query formed at the sequence's last position, the minimal case this lesson builds — compare that query against **every** key with a dot product, turn the comparisons into weights that sum to `1` with a **softmax**, and use those weights to form a weighted average of the **values**:

```
score_t  = (q_last · k_t) / sqrt(d_k)
weight_t = softmax(score)_t
context  = sum_t(weight_t * v_t)
```

`softmax` needs one primitive the M01 `Value` engine has never needed before: `.exp()`. Adding it is exactly the move M01 Lesson 2 taught — compute the forward value, attach the one-line local derivative as a closure:

```python
def exp(self):
    e = math.exp(self.data)
    out = Value(e, (self,), "exp")
    def _backward():
        self.grad += e * out.grad     # d(e^x)/dx = e^x, i.e. the output itself
    out._backward = _backward
    return out
```

**Why this removes Lesson 2's problem.** Trace the path from `x_0` to the loss through this graph: `x_0 → k_0 → score_0 → weight_0 (via softmax) → context → yhat → loss`. That is a fixed, small number of operations — it does **not** grow with `T`. Compare that to the RNN's path, which passes through `T` sequential `tanh`-and-matmul hops. Attention's context vector is a **weighted sum**, and the gradient of a sum with respect to one of its terms doesn't shrink because there are more *other* terms — `d(sum_t w_t*v_t)/dv_0 = w_0`, a single multiplication, not a chain of `T` of them.

**Worked example — a 4-token toy, traced fully.** `TinyAttention(input_size=1, d_k=3, seed=7)` on the scalar "sequence" `xs = [0.8, -0.3, 1.1, 0.4]`, forming the query from the last token (`x=0.4`):

| token | x_t | k_t | v_t | raw score (`q·k`) | scaled score (`/√3`) | weight |
|---|---|---|---|---|---|---|
| 0 | +0.80 | `[-0.252, -0.744, -0.171]` | `[0.890, 0.339, 0.830]` | -0.1110 | -0.0641 | 0.2438 |
| 1 | -0.30 | `[0.095, 0.279, 0.064]` | `[-0.334, -0.127, -0.311]` | 0.0416 | 0.0240 | 0.2663 |
| 2 | +1.10 | `[-0.347, -1.023, -0.235]` | `[1.223, 0.467, 1.141]` | -0.1526 | -0.0881 | 0.2381 |
| 3 | +0.40 | `[-0.126, -0.372, -0.085]` | `[0.445, 0.170, 0.415]` | -0.0555 | -0.0320 | 0.2518 |

The four weights sum to `1.0000` by construction. `context = sum(weight_t * v_t) = [0.5312, 0.2026, 0.4954]`. Notice the weights are *not* uniform (`0.25` each) — token 1's slightly higher weight (`0.2663`) reflects a genuinely higher query-key similarity, not an arbitrary tiebreak; this is what "attending more to some tokens than others" concretely is, arithmetically, nothing more mysterious than a dot product and a softmax.

**Worked example — the vanishing-gradient comparison, head to head.** Rerun Lesson 2's exact diagnostic (`|dL/dx_0|` vs. sequence length, 5-seed mean), this time on `TinyAttention` instead of `RNNCell`, same `T` values:

| T | RNN mean `\|dL/dx_0\|` | Attention mean `\|dL/dx_0\|` |
|---|---|---|
| 2 | 1.16e-01 | 3.37e-01 |
| 5 | 1.32e-01 | 9.21e-02 |
| 10 | 1.33e-02 | 7.46e-02 |
| 20 | 1.85e-03 | 5.06e-02 |
| 30 | 3.92e-04 | 4.84e-03 |
| 40 | 7.75e-06 | 4.96e-03 |
| 60 | 4.46e-08 | 2.24e-03 |
| 80 | 9.44e-11 | 3.46e-04 |

The RNN's `T=5`-to-`T=60` ratio is **`~2.97 million`**. Attention's is **`~41`**. Both numbers shrink — attention is not magically flat, and the next lesson explains exactly why it still shrinks a little — but a factor of `41` and a factor of `2,970,000` are not the same *kind* of number. One is a chain collapsing exponentially in `T`; the other is a single softmax's normalization getting divided across more competitors as `T` grows — a fundamentally gentler, non-compounding effect. Lab M04-B has you reproduce this exact table and hold both facts (still shrinks a little / categorically not the same collapse) at once, precisely because overclaiming the first fact ("attention never decays") is Named misconception 1 below, and this lesson is built to prevent it.

**Named misconception 1 — "attention has zero gradient decay with sequence length, unlike the RNN."** The table directly above refutes the strong version of this claim: attention's gradient at `T=80` (`3.46e-04`) is smaller than at `T=2` (`3.37e-01`) — about `1,000`x smaller. The correct, calibrated claim is narrower: attention removes the specific **multiplicative, chain-of-Jacobians** mechanism that makes the RNN's decay *exponential* in `T`. It does not remove every source of gradient dilution — softmax still divides a fixed unit of "attention mass" across more competitors as `T` grows, which is a real, measurable, but *polynomial-scale* effect, not the RNN's exponential one. "Categorically better" and "immune to sequence length" are different claims; only the first one survives contact with the numbers.

**Named misconception 2 — "attention needs a separate query source — you can't 'self-attend' the same sequence against itself."** Refuted directly by the mechanism just built: `Wq`, `Wk`, and `Wv` are all applied to vectors drawn from the *same* input sequence `xs`. Nothing about the mathematics requires the query to come from a different modality or a different network — this module's minimal version forms its one query from the sequence's own last token. (The historical order, worth naming explicitly: attention was first popularized attaching a decoder's query to an encoder's keys/values in machine translation — Bahdanau et al., 2014 — genuinely two different sequences. **Self**-attention, where *every* position in a single sequence also serves as a query against every other position, arrived later and is exactly what M05's transformer builds on top of this lesson's mechanism. You have already built the harder-to-name-but-identical arithmetic; M05 just runs it with every position as a query instead of one.)

### Lesson 4 — Softmax mechanics: why the scale factor is not optional

Lesson 3 built attention with two details stated but not yet justified: subtracting the max score before exponentiating, and dividing every score by `sqrt(d_k)`. Both are about the same underlying object — the softmax — and both turn out to be load-bearing, not decorative, which Lab M04-C will prove by breaking each of them in turn.

**Subtracting the max: numerically necessary, mathematically free.** `softmax(scores)_i = exp(scores_i) / sum_j(exp(scores_j))`. Algebraically, subtracting any constant `m` from every score changes nothing: `exp(scores_i - m) / sum_j(exp(scores_j - m)) = exp(scores_i)*exp(-m) / (exp(-m) * sum_j(exp(scores_j))) = exp(scores_i) / sum_j(exp(scores_j))` — the `exp(-m)` factor cancels top and bottom exactly. Choosing `m = max(scores)` guarantees every exponentiated term is `≤ 1` (never overflows) while the *answer* — the actual weight distribution — is provably identical to the un-shifted version. This is purely a floating-point safety measure; skip it and, for large enough scores, `math.exp` will raise `OverflowError` or silently produce `inf`, corrupting every downstream computation, but the *function being computed*, when it doesn't crash, was always the same function.

**The `1/sqrt(d_k)` scale: not numerical safety, a variance argument — the exact move M02 Lesson 1 made for weight initialization, now applied to dot products.** If `q` and `k` are `d_k`-dimensional vectors whose entries are independent with variance `≈ 1` each (a reasonable target if the projections feeding them are reasonably scaled), then `q·k = sum_{i=1}^{d_k}(q_i * k_i)` is a sum of `d_k` independent terms, each with variance `≈ 1` (the product of two independent unit-variance variables has variance `1`). Variances of independent terms add — the *identical* bookkeeping move from M02 Lesson 1's `Var(z) = fan_in * std² * Var(x)` — so `Var(q·k) ≈ d_k`. As `d_k` grows, raw dot-product scores grow with it (`std(q·k) ≈ sqrt(d_k)`), and **large-magnitude logits make softmax nearly one-hot**: one score dominates, its weight approaches `1`, every other weight approaches `0`. Dividing by `sqrt(d_k)` restores the score variance to `≈ 1` regardless of `d_k` — the same "keep the fixed point at 1" move Xavier/He initialization made for layer variance, just for the dot product feeding a softmax instead of the pre-activation feeding a `tanh`/`ReLU`.

**Worked example — the scale factor's absence, measured exactly.** Eight fixed "diagnostic" scores at `d_k=64` (so the correct scale is `1/√64 = 0.125`):

```
raw_scores = [8.2, 7.9, -1.1, 0.3, -4.6, 2.1, 5.9, -0.8]
```

| token | raw score | **unscaled** weight | **scaled** (`× 0.125`) weight |
|---|---|---|---|
| 0 | +8.2 | 0.542326 | 0.227708 |
| 1 | +7.9 | 0.401765 | 0.219327 |
| 2 | -1.1 | 0.000050 | 0.071205 |
| 3 | +0.3 | 0.000201 | 0.084823 |
| 4 | -4.6 | **0.000001** | **0.045973** |
| 5 | +2.1 | 0.001216 | 0.106225 |
| 6 | +5.9 | 0.054373 | 0.170812 |
| 7 | -0.8 | 0.000067 | 0.073926 |

Unscaled, tokens 0 and 1 alone soak up `94%` of the attention mass, and token 4 gets a weight of `1.5e-06` — for practical purposes, zero. A softmax weight's own local backward-pass gradient factor is `w*(1-w)` (a direct consequence of the derivative of the sigmoid-shaped softmax function); at `w = 1.5e-06`, that factor is `≈ 1.5e-06` too — **the gradient reaching token 4 has vanished**, not because of a chain of `T` multiplications this time, but because softmax itself saturated into a near-one-hot distribution. Scaled, token 4's weight is a healthy `0.046` and its local gradient factor is `0.044` — a recovery of **`~29,300`x**. Read that against this module's whole arc: attention was built specifically to escape the RNN's vanishing gradient, and a single missing scale factor reintroduces a structurally identical failure — smaller in scope (one softmax, not a whole sequence of timesteps) but the same underlying mechanism: a saturated nonlinearity with a near-zero local derivative. Lab M04-C is built to make you find, and fix, exactly this.

**Named misconception 1 — "subtracting the max before exponentiating changes softmax's output, so it's a tradeoff between stability and correctness."** Refuted by the algebra above: the `exp(-m)` factor cancels exactly, top and bottom. There is no tradeoff — the max-subtraction is free correctness-wise and mandatory numerically. A learner who treats it as "a small approximation for safety" has the relationship backwards: it is an exact identity, not an approximation.

**Named misconception 2 — "the `1/sqrt(d_k)` factor is a tunable hyperparameter, like a learning rate — worth trying a few values of, but not going to break anything if you skip it."** Directly refuted by the table above: skipping it is not "a slightly worse choice," it is a **`~29,300`x** collapse in the gradient reaching a specific token, measured, not estimated. It is derived from a variance argument with a single correct answer for a given `d_k` (mirroring He/Xavier's derivation in M02 Lesson 1), not tuned by trial and error — and Lab M04-C's debugging drill is built precisely because "I'll add scaling in later if it seems to help" is exactly the failure mode this lesson exists to close off.

import random

import math
import random
from value import Value
from lab_a_solution import make_matrix, matvec, Readout


def dot(a, b):
    return sum((ai * bi for ai, bi in zip(a, b)), Value(0.0))


def softmax(scores):
    m = max(s.data for s in scores)
    shifted = [s - m for s in scores]
    exps = [s.exp() for s in shifted]
    total = sum(exps, Value(0.0))
    return [e / total for e in exps]


class TinyAttention:
    def __init__(self, input_size, d_k, seed=0):
        rng = random.Random(seed)
        std = math.sqrt(1.0 / input_size)
        self.Wq = make_matrix(d_k, input_size, std, rng)
        self.Wk = make_matrix(d_k, input_size, std, rng)
        self.Wv = make_matrix(d_k, input_size, std, rng)
        self.d_k = d_k

    def __call__(self, xs_values):
        keys = [matvec(self.Wk, x) for x in xs_values]
        vals = [matvec(self.Wv, x) for x in xs_values]
        q = matvec(self.Wq, xs_values[-1])
        scale = self.d_k ** -0.5
        scores = [dot(q, k) * scale for k in keys]
        weights = softmax(scores)
        context = [Value(0.0) for _ in range(self.d_k)]
        for w, v in zip(weights, vals):

        return context, weights

    def parameters(self):
        ps = []
        for M in (self.Wq, self.Wk, self.Wv):
            ps += [w for row in M for w in row]
        return ps

## Assessment

Maps to the course's **build milestones** component (an RNN or attention block trained without this module's discipline will reproduce the exact failure modes measured here, just discovered later and more expensively) and the **broken-run clinics** component, which Lab M04-C is the direct rehearsal for.

**The unseen exam artifact.** The learner receives a short attention or RNN implementation (source code, no test suite, no training log commentary) with exactly **one planted bug**, drawn from this module's bug-family taxonomy:

1. **Missing `1/sqrt(d_k)` attention scale** (Lab M04-C's own bug family, on unseen code). Signature: attention weights are nearly one-hot (one or two tokens dominate `>90%` of the mass) on inputs where a healthy model should spread attention more broadly; gradients to any non-dominant token are many orders of magnitude smaller than the dominant token's.
2. **Weight sharing broken in the RNN cell** — fresh `Wxh`/`Whh`/`bh` `Value` objects created inside `step()` on every call instead of reused from `__init__`. Signature: `cell.parameters()` returns a list whose length scales with sequence length instead of staying fixed; the model cannot be evaluated on a sequence length different from the one it happened to be built for; training loss on any single sequence looks plausible in isolation because each timestep is effectively an independent, never-reused set of weights, but nothing generalizes across sequences.
3. **Softmax missing the max-subtraction, at a score scale large enough to matter.** Signature: works cleanly on short sequences or small `d_k`, then raises `OverflowError` or starts producing `nan`/`inf` losses once scores get moderately large (longer sequences, bigger `d_k`, or simply after enough training steps have grown the weights) — a "works until it doesn't" bug, distinguishable from bug 1 by *when* it manifests (a crash, not silently degraded gradients).
4. **Softmax normalized along the wrong axis** (across the `d_k` feature dimension of a token's own key vector instead of across the `T` sequence positions being compared for one query). Signature: the returned "weights" for a given query do not sum to `1` across positions; the context vector's magnitude scales unpredictably with `d_k` rather than always being a bounded average of the value vectors; the bug is invisible from the softmax function itself (which is correct in isolation) and only visible from *which axis it was called on*.

## Three-tier reading

Specific to this module's subject: the field's own move from recurrence to attention, and what "we replaced the bottleneck" turned out to actually mean once it shipped.

- **Tier 1 — material ground.** The vanishing-gradient problem in recurrent networks is not folklore — it is documented in the field's own foundational literature (Hochreiter's 1991 diploma thesis; Bengio, Simard & Frasconi, "Learning Long-Term Dependencies with Gradient Descent is Difficult," 1994), well before attention existed as a fix. Attention itself was introduced to address a sequence-modeling bottleneck years before the word "transformer" existed: Bahdanau, Cho & Bengio's 2014 "Neural Machine Translation by Jointly Learning to Align and Translate" attached an attention mechanism to an encoder-decoder RNN specifically to let the decoder access distant source words directly, without funneling everything through one fixed-size hidden state. The mechanism this module built from scratch — a query, a set of keys and values, a softmax-weighted sum — is that same idea, minimal and unmodified, three years before "Attention Is All You Need" (Vaswani et al., 2017) removed the RNN entirely and built a whole architecture on nothing but attention.
- **Tier 2 — what the field suppresses.** "Attention solves the long-range dependency problem" is the sentence that gets repeated; this module's own Lab M04-B numbers are the counter-evidence sitting right next to it. Attention's gradient at `T=80` was **not** the same as at `T=2` — it was roughly `1,000`x smaller, a real, measured, and *structurally distinct* decay from the RNN's exponential collapse, but a decay nonetheless. The field's popular narrative compresses "attention removes the specific multiplicative chain-of-Jacobians mechanism" into "attention has no long-range problem," and that compression has real consequences: production transformer systems, at far larger scale than this module's toy, still show measurable degradation in how well they use information from very distant parts of a long context — a phenomenon documented under names like "lost in the middle" in later scaling and evaluation literature. This module's own softmax-dilution number, small as it is, is the same story in miniature: fixing one specific, nameable bottleneck is not the same claim as removing every bottleneck, and the field's shorthand for what attention accomplished has, at times, quietly elided the difference.
- **Tier 3 — sit with this.** You built attention because it fixes a specific, provable failure — you watched the RNN's gradient collapse by 27 orders of magnitude and then watched attention not do that, on numbers you generated yourself. That is real, earned understanding of *why* attention was worth building. But the field that built it did not, from the equation alone, predict everything that followed from removing the sequential bottleneck: architectures built on attention turned out to support behaviors — in-context learning chief among them — that nobody derived on paper from "queries, keys, values, softmax" before they were observed empirically in trained models, years later, at scale nobody had tried before. You understand the mechanism you built completely: every weight, every gradient, every line. The course's own thread has been asking, since M01, what "understanding the architecture" does and doesn't buy you. Here is the sharpest version yet: if the fix for one well-understood, precisely diagnosed problem (vanishing gradients over sequences) turned out to unlock capabilities nobody derived from the fix itself — what should that tell you to expect, and to guard against, the next time you ship a fix for a problem you understand perfectly?
