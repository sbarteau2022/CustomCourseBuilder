## Lessons

### Lesson 1 — The loss landscape is a function, and convexity is a promise about its shape

**The teaching.** A "loss landscape" sounds like terrain you could hike. Strip the metaphor and it is exactly what M03 called `f`: a scalar-valued function of a parameter vector, `L: ℝⁿ → ℝ`. Nothing new has been added — not a new object, just a new *habit of reading*: you now look at `L(θ)` over the whole space of `θ`, not just at one point and its gradient.

Two tools make that whole-space view concrete. A **level set** (or contour) at height `c` is the set of points `{θ : L(θ) = c}` — everywhere the loss takes the same value. For `f(x,y) = x² + 3y²`, the level set at `c` is the ellipse `x² + 3y² = c`, with semi-axis `√c` along `x` and the smaller semi-axis `√(c/3)` along `y`. The axis with the *smaller* semi-axis is the axis where the function climbs *faster* — contour lines packed close together mean steep curvature, exactly the `y`-direction here, and this elongation is the entire subject of Lesson 2.

The second tool is **convexity**, and it is a formal claim, not a vibe: `f` is convex iff for every pair of points `θ₁, θ₂` and every `t ∈ [0,1]`,

```
f(t·θ₁ + (1−t)·θ₂)  ≤  t·f(θ₁) + (1−t)·f(θ₂)
```

Read it as "the straight chord between any two points on the graph lies on or above the graph." For a twice-differentiable function of one variable this reduces to a number you can compute: `f''(x) ≥ 0` everywhere. In many variables, the analogous object is the **Hessian** — the matrix of second partial derivatives — and `f` is convex where the Hessian is positive semi-definite (all eigenvalues `≥ 0`). The single fact that makes convexity worth checking: **for a convex function, every local minimum is a global minimum, and gradient descent with a small-enough learning rate is guaranteed to find it.** That guarantee is the whole reason classical optimization theory obsessed over convexity — and the whole reason Lesson 4 has to walk it back for deep nets.

**Worked example — convex bowl vs. nonconvex double well, checked by second derivative.**

Take `f(x,y) = x² + 3y²`, the bowl from M03. Its Hessian is constant: `f_xx = 2, f_yy = 6, f_xy = 0`, so `H = [[2,0],[0,6]]` — both eigenvalues positive, everywhere, for every `(x,y)`. This function is convex on all of `ℝ²`, with a single global minimum at the origin. No amount of exploring the landscape will ever reveal a second, different minimum.

Now take `f(x) = x⁴ − 2x²`, a **double well**. `f'(x) = 4x³ − 4x = 4x(x² − 1)`, with critical points at `x = 0, 1, −1`. The second derivative is `f''(x) = 12x² − 4`:

```
f''(0)  = −4   (negative → local MAX, a hump)
f''(1)  =  8   (positive → local min, f(1)  = 1 − 2 = −1)
f''(−1) =  8   (positive → local min, f(−1) = 1 − 2 = −1)
```

`f''(x) < 0` exactly on `|x| < 1/√3 ≈ 0.577` — this function is **not convex**; it is convex on the two outer wings and concave in the middle hump. It has **two** global minima (tied at `−1`) separated by a local max. A function like this cannot promise "any local min is the global min," because it has two different local minima that are not the same point. This is not a pathological toy — it is the simplest possible model of the reality Lesson 4 confronts head-on: deep-net losses look like a million-dimensional version of this, riddled with wells.

**Named misconceptions:**

- **"The loss landscape is a real physical valley, and the parameters are literally a ball rolling downhill."** Useful picture, wrong physics. There is no momentum, no inertia, no gravity unless an algorithm (Lesson 2's momentum-adjacent ideas, AIE-202's `SGD(momentum=...)`) explicitly adds a velocity term. Plain gradient descent has no memory of where it came from — every step is computed fresh from the current point's gradient alone. Believing otherwise is why learners are surprised gradient descent can reverse direction instantly when the local gradient flips.
- **"Convex means round or bowl-shaped."** `x² + 3y²` is convex and dramatically elongated — a valley, not a bowl. A flat plane `f(x) = 3x + 1` is also (trivially) convex, and has no minimum at all. Convexity is about the chord-above-curve inequality, not about symmetry or shape.
- **"If an algorithm converges, the function it was minimizing must be convex."** Backwards. Convergence describes an *algorithm's behavior on a run*; convexity describes a *property of the function*. Gradient descent can converge (to a local minimum, or get trapped near a saddle — Lesson 4) on a wildly nonconvex function; it simply loses its global guarantee when it does.
- **"A local minimum is always the global minimum."** True only under convexity. The double well has two distinct local minima, both global (tied); a slightly asymmetric double well would have one local minimum that is strictly worse than the other, and gradient descent, started on the wrong side, would confidently converge to it and report a low, "converged" loss.

### Lesson 2 — Gradient descent through curvature: condition number and the zig-zag

**The teaching.** M03 gave you the descent rule `x_new = x − η∇f(x)` and one worked warning: past a threshold learning rate, the loss explodes. This lesson makes that threshold *directional*, because real landscapes are almost never equally curved in every direction — and that asymmetry, not the learning rate alone, is what governs how gradient descent actually behaves.

Take the diagonal quadratic `f(x) = ½xᵀAx` with `A = diag(λ₁, …, λₙ)`, `λᵢ > 0`. The gradient is `∇f(x) = Ax`, so a descent step updates each coordinate *independently*:

```
xᵢ_new = xᵢ − η·λᵢ·xᵢ = xᵢ·(1 − η·λᵢ)
```

After `t` steps, coordinate `i` sits at `xᵢ(t) = (1 − ηλᵢ)ᵗ·xᵢ(0)`. That coordinate converges to `0` iff `|1 − ηλᵢ| < 1`, i.e. **iff `0 < η < 2/λᵢ`** — exactly M03's one-dimensional cliff, now stated per coordinate. The learning rate that keeps the *whole* trajectory stable is bounded by the **steepest** direction:

```
η_max  =  2 / λ_max
```

even if every other direction could tolerate a much larger step. This is the single most important fact in the lesson: **one global learning rate is always hostage to the worst-conditioned direction in the landscape.**

The ratio `κ = λ_max / λ_min` is the **condition number**. A landscape with `κ` near `1` is nearly spherical — descent marches straight to the minimum. A landscape with large `κ` is a long, narrow ravine — the largest safe step is small (bounded by the steep walls) while the shallow floor decays slowly, forcing many iterations. The learning rate that minimizes the worst-case decay rate over both extreme directions balances them exactly:

```
η*  =  2 / (λ_min + λ_max)          →   decay rate at η*:  (κ − 1)/(κ + 1)
```

**Worked example — the ellipse bowl, three learning rates, one condition number.**

`f(x,y) = x² + 3y²` again, `A = diag(2, 6)`. Read off the numbers directly:

```
λ_min = 2,  λ_max = 6   →   κ = 6/2 = 3
per-axis thresholds:    x stable for η < 2/2 = 1        y stable for η < 2/6 ≈ 0.333
η* = 2/(2+6) = 0.25      predicted decay rate = (3−1)/(3+1) = 0.5  (both axes, every step)
```

Starting at `(1, 1)`, hand-verify `η* = 0.25`: `x₁ = 1·(1 − 0.25·2) = 1·0.5 = 0.5`, `y₁ = 1·(1 − 0.25·6) = 1·(−0.5) = −0.5`. Both coordinates shrink by exactly `0.5` in magnitude every step — you can already see `x₂ = 0.25, y₂ = 0.25`, and so on, geometrically. Compare with `η = 0.1`: `x`'s multiplier is `1 − 0.2 = 0.8` — barely decaying — while `y`'s is `1 − 0.6 = 0.4`. The worst (slowest) coordinate at `η = 0.1` decays at `0.8` per step; at the balanced `η* = 0.25` the *worst* coordinate decays at only `0.5` per step. **`η* = 0.25` reaches any given tolerance faster than `η = 0.1`, even though `0.1` "feels" more cautious** — caution that is spent entirely on the direction that didn't need it.

Now push past the cliff for the steep axis only: `η = 0.4`. `x`'s multiplier is `1 − 0.8 = 0.2` (still fine, converging quickly). `y`'s multiplier is `1 − 2.4 = −1.4` — magnitude greater than `1`, so `y` **diverges, flipping sign and growing** every step: `y₀=1, y₁=−1.4, y₂=1.96, y₃=−2.744, …`. Meanwhile `x` is shrinking nicely toward `0`. **A learner watching only the `x` trace would see healthy convergence right up until the `3y²` term detonates the total loss.** This is the zig-zag's sharper cousin: not oscillation-that-still-shrinks, but one coordinate quietly exploding while another looks fine, because a single `η` was legal for one axis and illegal for the other.

**Named misconceptions:**

- **"One learning-rate threshold governs the whole landscape."** There is one threshold *per direction* (per eigenvalue of the Hessian), and the global `η` is always bounded by the steepest one. A learning rate that is perfectly stable for most of the parameters can be silently unstable for the few steep ones — and in a real network, "the few steep directions" are often exactly the parameters closest to the output, since gradient magnitude compounds through depth (M03 Lesson 4's chain-rule product).
- **"If the printed loss is decreasing, training is healthy."** A blended, whole-landscape loss can look fine for a while even when one internal direction is quietly diverging, if that direction's contribution starts small (as `y` above does, at `y₀=1`) — the total loss `x²+3y²` will eventually show it once `3y²` dominates, but "eventually" can be many steps into a run that looked clean at first glance.
- **"Condition number is a detail; only the learning rate matters."** The condition number sets a *ceiling* on how fast even the best-tuned `η*` can converge (`(κ−1)/(κ+1)` per step). A poorly conditioned landscape (unnormalized features, wildly different parameter scales) is slow no matter how carefully you tune `η` — which is the actual reason feature scaling and normalization layers (later modules) exist; they are conditioning fixes, not accuracy tricks.
- **"A smaller `η` is always the safe choice."** Safe, but not free — Lesson's own numbers show `η=0.1` converges strictly slower than the balanced `η*=0.25` on the *same* landscape. "Safe" and "fast" trade off, and the trade is governed entirely by `κ`.

### Lesson 3 — Stochastic gradient descent: an unbiased gradient with a computable amount of noise

**The teaching.** Full-batch gradient descent computes `∇L(θ) = (1/N)Σᵢ ∇ℓᵢ(θ)` — the exact average gradient over *every* training example — before taking a single step. For `N` in the millions, that is one step per O(N) work. **Stochastic gradient descent (SGD)** takes the step using a much cheaper estimate: the average gradient over a random **minibatch** of size `m ≪ N`,

```
ĝ = (1/m) Σ_{i ∈ batch} ∇ℓᵢ(θ)
```

The load-bearing fact, and the one most often misremembered, is this: **a properly random minibatch gradient is not a worse gradient — it is an unbiased estimator of the exact one.** Averaged over every possible random batch, `E[ĝ] = ∇L(θ)` exactly. What a smaller batch buys you is not bias, it is **variance** — `ĝ` is noisier around the same true value, and that noise shrinks roughly like `1/√m` (exactly like a sample mean in statistics, because that is precisely what it is).

**Worked example — the same gradient, six different batches, one dataset, exhaustively checked.**

Four data points `c = [1, 2, 3, 10]` (note the outlier at `10`), loss `ℓᵢ(w) = (w − cᵢ)²`, so `L(w) = mean(ℓᵢ(w))` and the exact gradient is `∇L(w) = mean(2(w − cᵢ))`. At `w = 0`:

```
∇L(0) = mean(2·(0−1), 2·(0−2), 2·(0−3), 2·(0−10)) = mean(−2,−4,−6,−20) = −32/4 = −8
```

Now every size-2 minibatch gradient at the same point, `ĝ = mean(2(0−cᵢ), 2(0−cⱼ))` for each pair:

```
{1,2} → −3    {1,3} → −4    {1,10} → −11
{2,3} → −5    {2,10} → −12  {3,10} → −13
```

Average all six: `(−3−4−11−5−12−13)/6 = −48/6 = −8` — **exactly the full gradient**, recovered from nothing but averaging noisy estimates. Any single one of them, though, can be far off: the `{3,10}` batch says `−13` (a `62%` overestimate in magnitude) purely because it happened to draw the outlier; the `{1,2}` batch says `−3` (a `62%` underestimate) purely because it missed it. Neither batch is *wrong* — both are unbiased draws from the same distribution, and the outlier is why the spread is large.

The spread is computable, not just a feeling. The variance across all six size-2 estimates is `16.67` (worked from the six values above); across all four size-1 estimates (`−2, −4, −6, −20`) it is `50`; the single size-4 ("full batch") estimate has variance `0` — there is only one possible batch when the batch is everything. These three numbers obey the exact finite-population relationship

```
Var(m)  =  Var(1) · (N − m) / (m · (N − 1))
```

Check it: `Var(2) = 50·(4−2)/(2·3) = 50·2/6 = 16.67` ✓. `Var(4) = 50·(4−4)/(4·3) = 0` ✓. For `m ≪ N` (the real-world regime — batches of `32` drawn from millions of examples), the correction factor `(N−m)/(N−1)` is essentially `1`, and the formula collapses to the familiar `Var(m) ≈ Var(1)/m` — variance falls off like `1/m`, standard deviation like `1/√m`. **Doubling the batch size does not halve the noise; it divides it by `√2`.**

Why trade an exact, low-variance gradient for a cheap, noisy one at all? Two reasons, and both matter. First, cost: `N` full-batch steps' worth of compute buys roughly `N/m` noisy SGD steps, and in practice many cheap noisy steps beat few expensive exact ones for the same total compute. Second — and this is the hook into Lesson 4 — the noise is not purely a tax. A minibatch gradient at a point where the *true* gradient is nearly flat can still point in a useful direction, because different batches see different local curvature; this is part of why SGD can escape terrain that traps plain full-batch GD.

**Named misconceptions:**

- **"The minibatch gradient is a biased approximation of the true gradient."** No — properly sampled (uniformly at random), it is **unbiased**; its problem is variance, not bias. This distinction has teeth: a biased estimator is systematically wrong even with infinite averaging, while an unbiased noisy one becomes exact on average, and many small noisy steps genuinely progress toward the true minimum. Conflating "noisy" with "wrong" is why learners distrust a perfectly correct training curve that jitters.
- **"Halving the batch size doubles the noise."** The relationship is `1/√m` in standard deviation (`1/m` in variance), not linear. Going from `m=4` to `m=1` in the worked example takes variance from `0` to `50` — not a modest bump, because you left the low-variance regime entirely, but the *rate* is still governed by the square-root law, not a doubling-for-halving rule.
- **"A single bad-looking minibatch gradient means something is broken."** A gradient of `−13` against a true value of `−8` (the `{3,10}` batch above) is expected sampling variability from a small sample containing an outlier, not evidence of a bug. The fix for high per-step variance is more steps, a larger batch, or averaging — not distrust of the underlying computation.
- **"SGD's randomness is purely a necessary evil, tolerated only for speed."** It is tolerated for speed, but it is also frequently *useful*: the noise perturbs the trajectory away from exact adherence to the deterministic path plain GD would take, which — as Lesson 4 will show concretely — can matter enormously near flat, non-minimal regions of a nonconvex landscape.

### Lesson 4 — Convexity meets reality: saddle points, plateaus, and what "converged" actually claims

**The teaching.** Lesson 1's convex guarantee — any local minimum is the global minimum, and gradient descent with small enough `η` provably finds it — does not apply to deep-net losses. Those landscapes are wildly nonconvex, in millions of dimensions, and the shape that dominates them is not "many bad local minima" so much as **saddle points** and **plateaus** — and the difference matters because a naive read of the gradient cannot tell them apart from a genuine minimum.

A **saddle point** is a critical point (`∇f = 0`) that is a minimum along some directions and a maximum along others: the Hessian has both positive and negative eigenvalues. `f(x,y) = x² − y²` at the origin is the textbook case: `∇f(0,0) = [0,0]`, but the Hessian `diag(2,−2)` has one eigenvalue of each sign — walk along `x` and the origin is the bottom of a bowl; walk along `y` and it is the top of a hill. It is a mountain pass, not a valley floor.

Here is why saddles, not bad local minima, are the dominant obstacle in high dimensions. At a random critical point of an `n`-dimensional landscape, treat each of the `n` Hessian eigenvalue signs as roughly a coin flip. The probability that **all** `n` are positive — a genuine local minimum — falls off like `(1/2)ⁿ`, collapsing toward zero as `n` grows into the millions that describe a real network. Almost every critical point a high-dimensional gradient descent run encounters is a saddle. This reframes the classic fear "gradient descent will get stuck in a bad local minimum": empirically and theoretically, the more common failure is **crawling near a saddle or a plateau**, where the gradient is near zero not because you have arrived, but because the landscape is locally flat in most directions at once.

This is precisely why "the gradient is small" cannot, by itself, mean "training has converged to something good." **Convergence**, read honestly, is a statement about an *algorithm's trajectory*: the update step (or the gradient norm) has shrunk below some threshold, at whatever point the trajectory happened to be when that threshold was crossed. It says nothing about whether that point is a minimum, a saddle, or a slow crossing of a plateau — that requires checking curvature (or, cheaply, checking that the loss keeps decreasing over a *sustained* window, not a single reading), which most training loops never do.

**Worked example — a saddle-and-double-well landscape, hand-traced.**

`f(x,y) = x⁴ − 2x² + 3y²` — Lesson 1's double well in `x`, glued to Lesson 2's steep bowl in `y`. Gradient: `∇f = [4x³ − 4x, 6y]`. Critical points: `∂f/∂y = 6y = 0 → y = 0`; `∂f/∂x = 4x(x²−1) = 0 → x = 0, ±1`. Check the Hessian diagonal `(f_xx, f_yy) = (12x²−4, 6)` at each:

```
(0, 0):  Hessian diag(−4, 6)   →  mixed signs   →  SADDLE   (f = 0)
(±1,0):  Hessian diag(8, 6)    →  both positive →  true minima  (f = 1 − 2 + 0 = −1)
```

Start gradient descent exactly at the saddle, `(x₀,y₀) = (0,0)`: `∇f(0,0) = [4·0−4·0, 6·0] = [0,0]`, exactly zero. **A plain gradient-descent step does nothing, forever, in exact arithmetic** — `w` never moves, the loss sits at `f(0,0)=0`, and any stopping rule that checks "is the gradient small?" declares victory *immediately*, having found `L = 0` instead of the true minimum `L = −1`. This is not a contrived edge case: it is the formal reason deep-learning practice never initializes all weights to a symmetric, zero-gradient configuration.

Nudge the start slightly off the saddle, to `(0.01, 0.01)`, and use a stable learning rate (`η=0.1`, well under `y`'s `1/3` threshold from Lesson 2). The gradient there is `[4(0.01)³ − 4(0.01), 6(0.01)] ≈ [−0.04, 0.06]`, with norm `≈0.072` — already smaller than a common stopping threshold like `0.1`, even though the trajectory has barely begun and the true minimum (`L=−1`) is nowhere near reached. A *single* small-gradient reading here is a false alarm: run a few more steps and the `x` coordinate — sitting on the unstable side of a local max — begins to grow (its local curvature is `−4`, so nearby it behaves like `x·(1 + 4η)`, *expanding*, not contracting), and the gradient magnitude rises again as it escapes the flat shelf. **Only a stopping rule that requires the gradient to stay small over several consecutive steps — not one lucky reading — tells a plateau-crossing apart from a genuine minimum**, and Lab 2 / the capstone both build and break exactly this distinction.

**Named misconceptions:**

- **"A small gradient means you are at a good minimum."** It means the *local slope* is small — true at minima, at maxima, at saddles, and anywhere on a wide plateau. Telling these apart needs curvature information (the Hessian's eigenvalue signs) or, cheaply, sustained observation over several steps, not a single reading.
- **"Gradient descent explores the landscape and finds the best minimum."** GD is strictly local and greedy: at every step it knows only the gradient at its current point, nothing about the rest of the landscape. It converges to whichever basin its trajectory happens to fall into — the double-well example shows this literally: `x₀=0.1` and `x₀=−0.1` are separated by a hair's width and converge to opposite, tied-value minima at `+1` and `−1`.
- **"Since deep nets are nonconvex, gradient descent's practical success is basically unexplained/magic."** Overstated in both directions — there is no full theoretical guarantee like the convex case, but the concentration of critical points into saddles rather than bad local minima (the coin-flip argument above), combined with SGD's noise perturbing a trajectory off exact saddle-crawling paths, is a real, if incomplete, part of the explanation the field actively researches. Neither "it's proven" nor "it's a total mystery" is honest.
- **"Convergence means the algorithm found *the* answer."** Convergence means the update size (or gradient norm) fell under a threshold at whichever point a particular random start, minibatch order, and learning-rate schedule happened to land on. A different seed can converge to a materially different point with a similar loss — a fact Tier 2 below returns to directly.

```python
# solution.py
import numpy as np

def quadratic_grad(x, a):
    return np.asarray(a) * np.asarray(x)

def gradient_descent(grad_fn, x0, lr, steps):
    x = np.array(x0, dtype=float)
    hist = [x.copy()]
    for _ in range(steps):
        x = x - lr * np.asarray(grad_fn(x), dtype=float)
        hist.append(x.copy())
    return np.array(hist)

def condition_number(a):
    a = np.asarray(a)
    return float(np.max(a) / np.min(a))

def optimal_lr(a):
    a = np.asarray(a)
    return float(2.0 / (np.max(a) + np.min(a)))
```

# solution.py
import numpy as np

def double_well_grad(x):
    return 4*x**3 - 4*x

def gradient_descent_1d(grad_fn, x0, lr, steps):
    x = np.float64(x0)      # numpy float overflows to inf/nan, never raises
    hist = [x]
    for _ in range(steps):
        x = x - lr * grad_fn(x)
        hist.append(x)
        if not np.isfinite(x):
            break
    return np.array(hist)

def which_basin(x_final, tol=1e-2):
    if not np.isfinite(x_final):
        return None
    for target in (1.0, -1.0, 0.0):
        if abs(x_final - target) < tol:
            return int(target) if target != 0 else 0
    return None

**Solution.**

```python
# solution.py
import numpy as np
from itertools import combinations

C = np.array([1.0, 2.0, 3.0, 10.0])

def full_grad(w, c=C):
    return float(np.mean(2 * (w - c)))

def batch_grad(w, indices, c=C):
    sub = np.asarray(c)[list(indices)]
    return float(np.mean(2 * (w - sub)))

def all_batch_grads(w, m, c=C):
    n = len(c)
    return np.array([batch_grad(w, combo, c) for combo in combinations(range(n), m)])

def sgd(c, lr, steps, batch_size, rng, w0=0.0):
    w = float(w0)
    hist = [w]
    n = len(c)
    for _ in range(steps):
        idx = rng.choice(n, size=batch_size, replace=False)
        g = batch_grad(w, idx, c)
        w = w - lr * g
        hist.append(w)
    return np.array(hist)
```

## Three-tier reading

**Tier 1 — the material ground (verifiable facts).** A loss landscape is a scalar-valued function of parameters, nothing more exotic than the `f(x,y)` you have been differentiating since M03. Convexity is a checkable property (chord above curve; Hessian positive semi-definite) that, when present, guarantees any local minimum is the global one and that gradient descent with a small enough learning rate finds it. Gradient descent's stability is bounded, per direction, by `η < 2/λᵢ` for each Hessian eigenvalue `λᵢ`, and the worst direction sets the ceiling for the whole trajectory. A minibatch gradient, properly sampled, is an unbiased estimator of the full gradient with variance that falls as `1/m` — both facts you verified by exhaustively enumerating and averaging every possible batch, not by taking anyone's word for it. Saddle points, not bad local minima, dominate the critical points of high-dimensional nonconvex landscapes. None of this is a matter of opinion; every claim in this paragraph was hand-computed and then measured to agree, in this module's labs.

**Tier 2 — what the mathematical dressing suppresses.** "The model converged" sounds like a discovery — an objective, checkable fact about the world. Lesson 4 showed exactly what it actually claims: an update size or gradient norm fell under a threshold, at whichever point a particular random seed, minibatch order, and learning-rate schedule happened to land the trajectory. Two runs of the identical architecture on identical data, differing only in random seed, can both "converge," both report similarly low validation loss, and land at two genuinely different points in a nonconvex landscape — different basins, like the double well's `+1` and `−1`, potentially with different behavior on inputs neither training run happened to emphasize. The word "converged" carries none of that contingency; it reads as a terminus, a settled fact, when what actually happened was one particular trajectory's arrival at one particular, arbitrary-among-many-similar point. A learning-rate schedule, a batch size, an early-stopping patience counter — each is a value-laden choice about how much noise to tolerate and how early to trust a flat gradient, rendered invisible the moment a training run prints a single scalar loss and a boolean. Boosters say "the model was trained until convergence," which sounds like rigor; critics say "it just stopped when the numbers looked good enough," which sounds like nothing was decided. Both dodge the load-bearing fact: **convergence is a claim about where an algorithm's particular walk happened to stop, not a claim about the walk having found the best place to be — and the difference between those two claims is exactly the difference this module spent eighteen hours teaching you to check.**

All three runs "converge" — gradient norm below threshold, loss curves that look, by eye, identical. All three land in different regions of a nonconvex parameter space, the way this module's double well sends two hairs'-width-apart starting points to opposite basins. Nothing about the number you reported — the final validation loss — reveals that the other two exist, or that they might behave differently from the one you shipped on the exact input that later goes wrong for someone. This module taught you, precisely, why that convergence claim is real *and* incomplete: real, because the gradient genuinely did fall to near zero, checkably, the way you checked it by hand on paper; incomplete, because near-zero gradient tells you nothing about which of several structurally different resting points you are standing on. **The question you cannot unknow: which of the two or three basins you didn't ship — the runs whose seed you didn't pick, whose stopping point you'll never inspect — might have handled the case that matters to the person on the other end of this model's decision, and would "we picked the one with slightly lower validation loss" survive being said out loud to them?**
